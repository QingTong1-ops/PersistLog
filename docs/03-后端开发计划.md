### 0.1 本轮目标

做出 Phase 1 的可运行后端：

```text

→ 档案/目标
→ 上传 Markdown → AI 解析 → 预览 → 确认导入

→ 完成/延期/跳过/阻塞/放弃/顺延

```

- 前端/UI、小程序、桌面端。
- Phase 2 代码评审（接口/表预留，不实现）。
- Phase 3 AI 诊断、八股提问、错题复习、能力看板、平台数据交换。
- 沙箱、CLI/IDE、语音、多渠通知、管理后台。
- 真实第三方 AI 调用：API Key 为空，先用可替换的 Stub Provider。

## 2. 技术决策

| 项 | 选择 | 理由 |
|---|---|---|
| Web 框架 | FastAPI | 类型清晰、OpenAPI、适合 AI/文件 |
| ORM | SQLAlchemy 2.x（**同步**） | Phase 1 降低异步复杂度；需要时再迁 async |
| 驱动 | PyMySQL | 同步、稳定、易排查 |
| 迁移 | Alembic | 版本化 DDL |
| 校验 | Pydantic v2 | 请求/响应/AI Schema |
| 配置 | pydantic-settings + `.env` | 本地配置，密钥不入库 |
| 队列 | Celery + Redis | 导入、日计划、通知异步 |
| 测试 | pytest + httpx/TestClient | 单元 + API + MySQL 集成 |
| 认证 | JWT Access + Refresh Token | 独立登录 |
| 密码 | Argon2id | 安全默认 |
| AI | Provider 接口 + Stub + OpenAI-compatible | Key 为空也能开发/测试 |
| 文件 | 本地存储适配器（`storage/`） | 无 MinIO/Docker；接口不变，后续换 S3 |
| 通知 | NotificationProvider + Outbox | 企微适配器；测试用 Logging Provider |
| 时间 | 用户时区 + 日界线 04:00 | 与设计一致 |

### 2.1 为什么 Phase 1 用同步 SQLAlchemy

- 业务以 CRUD + 规则计算为主，同步足够。
- Celery Worker 本身是同步模型，复用同一套 Repository 更简单。
- FastAPI 的同步路由会跑在线程池，不会阻塞事件循环。
- 后续如果 AI/文件吞吐需要，再切 async SQLAlchemy；接口层不变。

## 5. 开发里程碑与提交计划

> 每个里程碑完成“代码 + 单测 + 迁移”后单独 commit；测试不通过不提交。

### M0：仓库初始化（本次）

- `git init -b main`
- `.gitignore`
- 本计划
- 初始 commit：`docs: add backend development plan`

### M1：后端骨架

- `pyproject.toml` / 依赖声明。
- `app/main.py`、配置、数据库、错误包、日志、健康检查。
- Alembic baseline（26 张表）。
- pytest 基础 fixture。
- 单测：健康检查、错误包、配置加载、时间工具。
- Commit：`chore: bootstrap FastAPI backend skeleton`
- 完成标准：`pytest` 可跑；`/health` 返回 200；迁移可执行。

### M2：认证、档案、目标、授权

- 表：`users`、`refresh_tokens`、`user_profiles`、`job_targets`、`user_consents`。
- 接口：register/login/refresh/logout、profile、job-targets、settings、consents。
- JWT/Refresh Token、Argon2id、限流占位。
- 单测/API 测试：注册登录、刷新、越权、目标 CRUD、授权记录。
- Commit：`feat(auth): add authentication and profile management`
- 完成标准：新用户可注册/登录/填档案/目标；Token 刷新正确。

### M3：文件与计划导入

- 表：`files`、`import_batches`、`import_items`、`import_issues`。
- 本地文件存储适配器；上传大小/类型校验。
- Markdown 解析器（标题/列表/checkbox/表格/日期）。
- `AIProvider` + `StubAIProvider`：返回固定路线草案。
- 校验器：必填/日期/容量/重复/开始日期。
- 接口：presign/complete、imports、preview、confirm、cancel、rollback。
- 单测：解析、校验、幂等确认、回滚、Stub AI。
- Commit：`feat(import): add markdown plan import pipeline`
- 完成标准：一份 Markdown 能生成预览并确认成路线。

### M4：路线、阶段、周、任务

- 表：`routes`、`route_versions`、`route_stages`、`route_weeks`、`tasks`、`task_dependencies`、`recurring_rules`。
- 路线 CRUD/激活/暂停/恢复/归档/调整/版本。
- 阶段/周/任务 CRUD；删除语义（归档/409）。
- 单测/API 测试：层级、版本、删除保护、容量校验。
- Commit：`feat(route): add route and task management`
- 完成标准：可手动维护路线，也能编辑导入结果。

### M5：每日计划与今日执行

- 表：`daily_plans`、`daily_plan_items`、`task_occurrences`。
- 生成器：输入池/容量/优先级/幂等/解释。
- 今日接口；开始/完成/延期/跳过/阻塞/解除/放弃/拆分。
- 顺延：日界线、剩余分钟、carry_over_from_id、postpone_count。
- 预测：剩余工作量/吞吐/forecast_end_date。
- 单测：生成幂等、容量、优先级、顺延、预测、时区。
- Commit：`feat(planning): add daily plan execution and carry-over`
- 完成标准：今天能看到任务并完成/顺延，第二天正确接续。

### M6：执行看板

- 聚合查询：完成率、计划/实际分钟、趋势、分布、顺延率、路线进度、预测。
- 接口：overview/trends/distribution/forecast。
- 单测：口径、对账、空数据、跨时区。
- Commit：`feat(dashboard): add execution dashboard`
- 完成标准：看板数字与今日页/数据库一致。

### M7：通知

- 表：`notification_channels`、`notification_templates`、`notification_preferences`、`notification_outbox`。
- 渠道 CRUD/测试；模板渲染；偏好；免打扰；Outbox/重试/去重。
- 企微适配器（Webhook 校验/SSRF 防护）；测试用 Logging Provider。
- Celery 任务：早报/晚报/逾期/顺延/周总结。
- 单测：渲染、去重、重试、SSRF、免打扰。
- Commit：`feat(notification): add WeCom notification pipeline`
- 完成标准：配置 Webhook 后能收到测试消息；失败可重试。

### M8：硬化与 E2E

- 审计日志、限流、错误码、日志脱敏、备份说明。
- E2E：注册→导入→今日→完成→看板→通知。
- OpenAPI 检查；迁移回滚；种子数据。
- Commit：`chore: harden phase 1 backend`
- 完成标准：验收清单全过，测试全绿。

## 6. 测试计划

### 6.1 单元测试（不依赖 MySQL）

- Markdown 解析、导入校验。
- 日计划选择、容量、优先级。
- 顺延/剩余分钟/预测。
- 看板指标口径。
- JWT/密码/加密/模板渲染/SSRF 校验。
- 时区/日界线/日期边界。

### 6.2 API 测试

- FastAPI TestClient + 依赖覆盖。
- 认证、档案、目标、导入、路线、今日、看板、通知。
- 越权：A 用户访问 B 资源返回 404/403。
- 错误包/分页/幂等。

### 6.3 集成测试

- MySQL `persistlog_test`，事务/清表。
- Celery `task_always_eager=True`。
- Stub AI，不访问网络。
- 本地存储临时目录。

### 6.4 覆盖率

- 核心 service/algorithm ≥80%。
- 不追求全局数字；关键路径必须有测试。
- 每个里程碑提交前跑 `pytest -q`。

## 7. API 与约定

- Base path `/api/v1`；OpenAPI `/docs`。
- 统一错误包：`{error:{code,message,details,request_id}}`。
- 分页：`page/page_size`。
- 异步：`202 {job_id}` + `GET /jobs/{id}`。
- 幂等：`Idempotency-Key`。
- 所有业务查询强制 `user_id`。
- 时间：UTC 存储，用户时区计算日期。

## 8. Git 工作流

- 分支：`main`。
- 一个功能模块一个 commit；测试和代码同 commit。
- Commit 格式：
  - `feat(module): ...`
  - `fix(module): ...`
  - `test(module): ...`
  - `chore: ...`
  - `docs: ...`
- 不提交：`.env`、`storage/`、`__pycache__`、`.pytest_cache`、本地依赖目录。
- 每次提交前：
  1. `pytest -q` 通过；
  2. `git status` 无敏感文件；
  3. 迁移可执行；
  4. 更新必要文档。
- 远程仓库由用户最后统一推送；本地不配置 remote。
