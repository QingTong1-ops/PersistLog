# 恒序 persistLog · 需求分析

**版本** v0.1（草案）  
**日期** 2026-10-19  
**范围** 产品定位、用户场景、功能需求、核心规则、MVP 边界  
**状态** 待评审

> 一句话：恒序把"简历与困境"翻译成"今天做什么"，把"今天做了什么"翻译成"能力有没有变强"，再用错题复习把短期练习变成长期记忆。

---

## 0. 结论先行

1. **产品本质**：不是 Todo，而是求职准备的"执行层"。用户不缺内容和工具，缺的是"今天做什么"和"做得怎么样"。
2. **三条闭环**：规划（目标→日计划）、反馈（提交→评分）、记忆（错题→复习）。任何一条断裂，产品都会退化为清单、题库或备忘录。
3. **核心资产**：用户能力画像、错题记忆、执行数据。任务列表只是这些资产的投影，不是资产本身。
4. **成败关键**：计划可执行、评分可信。为此"容量约束、保底模式、证据引用、人工校准"必须在 MVP 里，而不是以后再说。
5. **与平台的关系**：求职平台管内容、机会、评估；恒序管执行、反馈、记忆。先做深链，再做 SSO，最后做数据同步。
6. **MVP 取舍**：先做"路线 + 日计划 + 推送 + 评分 + 错题复习"，暂缓 QQ、SSO、本地目录监听、变式题。

## 1. 背景与问题定义

### 1.1 场景

求职期（秋招、春招、社招）是 3–6 个月的高强度、多线程、延迟反馈阶段。用户同时要处理：算法、八股、项目、简历、投递、面试、信息收集。

每天开始时要回答"今天做什么"，结束时却没有人告诉他"今天做得怎么样"。现有工具把这三个问题拆给了三个地方：计划在 Notion，题目在力扣，错题在备忘录，提醒靠脑子。结果是：**计划维护成本高于执行收益，最后放弃。**

### 1.2 痛点归因

| # | 用户原话 / 现象 | 问题本质 | 恒序的应对 |
|---|---|---|---|
| P1 | 缺乏系统规划 | 目标无法分解为可执行单元 | 简历/困境 → 诊断 → 阶段/周/日路线 |
| P2 | 每日任务缺少对齐度 | 任务与目标之间没有可追溯的关联 | 任务挂目标 + 计划/执行双对齐度 |
| P3 | 每日整理待办繁琐 | 计划维护成本高于执行收益 | 自动编排 + 推送即清单 + 零整理 |
| P4 | 无提醒，不知道做什么 | 缺少稳定的触发器和上下文 | 早/晚推送 + 上下文提示 |
| P5 | 想到什么做什么 | 缺少优先级与容量约束 | 收集箱 + 编排引擎 + 锁定期 |
| P6 | 练了但不知道有没有变强 | 缺少练习质量的反馈 | AI 评分 + 能力趋势 |
| P7 | 错题记了但不复习 | 缺少调度机制 | 间隔重复 + 自动入日计划 |
| P8 | 简历和困境没人给建议 | 缺少个性化诊断 | 简历解析 + 困境分析 + 路线 |

### 1.3 现有方案为什么不够

| 方案 | 解决什么 | 缺什么 |
|---|---|---|
| 通用 Todo（滴答清单、Notion） | 记录与提醒 | 不会拆解、不会评估、不会复习 |
| 学习平台（力扣、牛客、八股站点） | 内容与题目 | 没有个人计划、没有跨内容编排 |
| 通用 AI 对话 | 一次性建议 | 不落地、不跟踪、不记忆 |
| 求职平台 | 岗位、测评、题库、面试 | 不负责"每天执行" |
| 自习室 / 打卡群 | 氛围与监督 | 无个性化、无质量反馈 |

结论：市场不缺内容和工具，缺的是**把内容变成每天动作，并对动作质量负责**的系统。

### 1.4 机会判断

- 差异化不在题库，在"编排 + 评估 + 记忆"。
- 用户愿意为"每天不用想做什么"和"有人告诉我哪里不行"持续投入。
- 与现有求职平台是互补关系，不是替代关系。

## 2. 产品定位

### 2.1 一句话定义

恒序 persistLog 是面向计算机专业求职者的**每日执行与复盘智能体**：以简历和困境为起点生成系统化提升路线，自动编排每日任务，通过企业微信 / QQ 推送驱动执行，对算法、工程、八股练习进行评分与抽问，并用可配置的间隔复习把错题转化为长期记忆。

### 2.2 三条闭环

```text
                    ┌──────────────────┐
                    │   用户能力画像    │
                    └────────┬─────────┘
         ┌───────────────────┼───────────────────┐
         ▼                   ▼                   ▼
   ┌───────────┐       ┌───────────┐       ┌───────────┐
   │  规划闭环  │       │  反馈闭环  │       │  记忆闭环  │
   │ 目标→日计划│       │ 提交→评分  │       │ 错题→复习  │
   └─────┬─────┘       └─────┬─────┘       └─────┬─────┘
         │                   │                   │
         └──────────────► 每日执行 ◄─────────────┘
                             │
                             ▼
                       周复盘 / 重规划
```

- **规划闭环**：目标 → 路线 → 阶段 → 周 → 日 → 任务。
- **反馈闭环**：练习 → 提交 → 评分 → 改进 → 能力画像。
- **记忆闭环**：错误 → 错题 → 间隔复习 → 掌握。
- 三个闭环共用一份画像，互相供给：评分发现薄弱 → 影响明日计划；错题到期 → 进入今日任务；周复盘 → 触发重规划。

### 2.3 与求职平台的分工

| 能力 | 求职平台 | 恒序 | 关系 |
|---|---|---|---|
| 岗位门槛 / JD | 提供 | 消费 | 平台 → 恒序 |
| 测评 | 提供 | 消费结果 | 平台 → 恒序 |
| 题库 / 答题练习 | 提供 | 可调用、可回链 | 双向 |
| 社区 | 提供 | 不做 | — |
| 简历模板 / 解析优化 | 提供 | 消费解析结果 | 平台 → 恒序 |
| AI 面试官 | 提供 | 可回链、可预约 | 双向 |
| 每日计划 / 执行跟踪 | 不做 | 核心 | — |
| 练习评分 / 错题复习 | 不做 | 核心 | — |
| 推送触达 | 不做 | 核心 | — |

**边界原则**：平台负责"内容、机会、评估"，恒序负责"执行、反馈、记忆"。恒序不重复建设题库和社区。

### 2.4 非目标

- 不做题库内容生产、社区、招聘投递。
- 不做通用笔记 / 知识管理。
- 不替用户编造简历经历。
- 不做"打卡即成功"的虚荣指标。
- 不做心理诊断或医疗建议；困境分析限定在求职相关范围（技能、表达、时间、信息差、面试反馈）。
- 首版不做多租户 SaaS、团队协作、排行榜。

### 2.5 设计原则

1. **系统提议，用户确认**：AI 可以生成和调整，但路线/计划的大改必须经过确认；用户锁定项不被覆盖。
2. **可完成优先于理论最优**：计划必须落在真实时间预算内；宁可少而完成，不可多而崩溃。
3. **一切任务可溯源**：每个任务能回答"为了哪个目标、哪个能力项"。
4. **反馈必须具体**：评分要引用证据、给出不超过 3 条可执行改进；拒绝"继续加油"。
5. **零整理**：用户每天只需做三件事——确认、完成、跳过。
6. **数据属于用户**：可导出、可删除、可关闭 AI 处理。

## 3. 用户与场景

### 3.1 目标用户

| 画像 | 特征 | 核心诉求 | 优先级 |
|---|---|---|---|
| A. 秋招应届（本科/硕士） | 3–6 个月窗口，有 1–2 个项目，表达弱 | 系统规划 + 每日执行 + 面试表达 | 主 |
| B. 社招 / 转行 | 时间碎片，目标明确但缺方法 | 高效利用 1–2 小时/天 | 主 |
| C. 低年级找实习 | 时间充裕，方向不清 | 探索 + 基础打底 | 次 |
| D. 二战 / 脱产备考 | 自律要求高，易焦虑 | 节奏 + 反馈 + 陪伴 | 次 |

共同点：**有目标、缺拆解；有内容、缺反馈；有错题、缺复习。**

### 3.2 核心用户故事

| ID | 故事 | 价值 | 优先级 |
|---|---|---|---|
| US-01 | 作为求职者，我上传简历并描述困境，希望得到一份能直接执行的提升路线 | 解决"不知道从哪开始" | P0 |
| US-02 | 作为用户，我希望每天早上收到今天的任务清单，不需要自己整理 | 解决"每天想做什么" | P0 |
| US-03 | 作为用户，我完成算法题后提交代码，希望得到具体评分和改进建议 | 解决"练了没反馈" | P0 |
| US-04 | 作为用户，我希望系统每天问我几道八股 / 项目题，并记录我的错题 | 解决"学了就忘" | P0 |
| US-05 | 作为用户，我希望错题按 1/3/7/14 等间隔自动出现在任务里 | 解决"错题不复习" | P0 |
| US-06 | 作为用户，我希望看到今天做的事和本周目标是否对齐 | 解决"瞎忙" | P0 |
| US-07 | 作为用户，我希望从求职平台一键跳到恒序，带着岗位和测评结果生成计划 | 降低启动成本 | P1 |
| US-08 | 作为用户，我希望导入其他 AI 给我的 markdown 学习计划 | 利用已有资产 | P1 |
| US-09 | 作为用户，我希望周末看到一周报告和下周重点 | 形成节奏 | P1 |
| US-10 | 作为用户，我希望计划落后时系统自动帮我重排，而不是堆成山 | 防止放弃 | P1 |

### 3.3 典型一天

- **07:30** 企微收到早报：今日 4 项、预计 2h10m、本周重点"项目表达"、昨日错题 2 道。
- **08:00** 通勤时点开今日页，浏览任务，把"项目架构图"顺延到周末（一键）。
- **09:30** 算法 2 题，提交代码 + 复杂度说明 + 自测结果。
- **10:10** 收到评分：72 分，边界条件遗漏，生成 2 道错题，明日复习。
- **14:00** 项目任务：补架构图与取舍说明，提交文档链接。
- **20:30** 晚间推送：今日完成 3/4，对齐度 82%，1 道错题待复习。
- **21:00** 日复盘：3 个问题（最大收获 / 最大卡点 / 明日调整），30 秒完成。
- **21:05** 系统生成明日计划，D+1 错题自动进入。

### 3.4 用户旅程与流失点

| 阶段 | 目标 | 关键动作 | 流失风险 | 对策 |
|---|---|---|---|---|
| 认知 | 理解价值 | 看到"路线 + 每日推送" | 以为是又一个 Todo | 首屏演示"简历→路线→今日" |
| 激活 | 完成首次配置 | 目标 / 简历 / 困境 / 时间 | 问卷太长 | 5 分钟内完成；可跳过；渐进补全 |
| 首次价值 | 拿到路线和首日计划 | 预览 / 调整 / 确认 | 路线太泛 | 必须细化到日，有产出、有验收 |
| 习惯 | 连续 7 天执行 | 推送 → 完成 → 复盘 | 第 3 天落后 | 保底模式 / 自动降载 / 顺延 |
| 留存 | 看到能力变化 | 周报 / 趋势 / 掌握率 | 感觉没进步 | 可视化 + 具体对比 |
| 传播 | 推荐 | 分享周报 | — | P2 |

## 4. 总体方案

### 4.1 功能架构

```text
┌──────────────────────────────────────────────────────────────┐
│ 触达层   企业微信 / QQ / 邮件 / Web / 移动端（P1）              │
├──────────────────────────────────────────────────────────────┤
│ 交互层   今日 / 计划 / 练习 / 错题 / 路线 / 报告 / 设置          │
├──────────────────────────────────────────────────────────────┤
│ 智能体层 Planner / Coach / Examiner / Reviewer / Importer      │
├──────────────────────────────────────────────────────────────┤
│ 核心服务 计划编排 / 评分 / 复习调度 / 推送 / 导入 / 联动         │
├──────────────────────────────────────────────────────────────┤
│ 数据层   画像 / 简历 / 路线 / 任务 / 提交 / 评分 / 错题 / 日志   │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 核心对象关系

```text
求职目标 Goal
  └─ 路线 Roadmap（版本化）
       └─ 阶段 Stage
            └─ 周计划 WeekPlan
                 └─ 任务 Task ──► 每日计划项 DailyPlanItem
                      │
                      ├─► 练习 Submission ──► 评分 Evaluation
                      │                          └─► 错题 Mistake
                      │                                   └─► 复习 ReviewRecord
                      └─► 能力维度 AbilityMetric
```

说明：任务可以不属于路线（手动、导入、复习），但必须标注来源；复习任务由错题派生，不进路线。

### 4.3 计划体系（五层）

| 层级 | 周期 | 内容 | 谁生成 | 变更频率 |
|---|---|---|---|---|
| 求职目标 | 3–12 个月 | 岗位、批次、截止日、优先级 | 用户 | 低 |
| 路线 | 4–16 周 | 诊断、策略、阶段、周主题、产出 | AI + 用户确认 | 低 |
| 阶段 | 2–4 周 | 目标、能力项、验收标准 | AI / 用户 | 中 |
| 周计划 | 1 周 | 本周重点、里程碑、任务池 | AI 生成 + 用户调整 | 中 |
| 日计划 | 1 天 | 3–6 个任务、预计时长、聚焦语 | 系统编排 | 每日 |
| 周期计划 | 每日 / 每周 / 每两周 | 固定动作（如每日 1 题、周日晚复盘） | 用户 / 模板 | 低 |

### 4.4 任务模型

任务是最小执行单元。建议字段：

| 字段 | 说明 | 必填 |
|---|---|---|
| type | 算法 / 八股 / 工程 / 项目 / 简历 / 投递 / 复盘 / 面试 / 复习 | 是 |
| title | 动作 + 对象，如"手写 LRU，要求 O(1)" | 是 |
| content | 具体做什么、范围、参考资料 | 是 |
| deliverable | 产出物（代码 / 图 / 文档 / 口述录音 / 题解） | 是 |
| acceptance | 验收标准（可检查） | 是 |
| est_min | 预计时长 | 是 |
| ability_tags | 关联能力维度 | 是 |
| goal_id / stage_id / week_id | 溯源 | 路线任务必填 |
| priority | P0 / P1 / P2 | 是 |
| difficulty | 1–5 | 否 |
| dependency | 前置任务 | 否 |
| due_date | 截止日 | 否 |
| source | roadmap / manual / import / review / recurring | 是 |
| locked | 锁定，不被重规划改动 | 否 |

**颗粒度规则**：单个任务 15–90 分钟；超过 90 分钟必须拆分；小于 15 分钟可合并。产出与验收缺一不可，否则不允许进入日计划。

### 4.5 状态机

**任务**：待办 → 进行中 → 完成 / 部分完成 / 跳过 / 顺延 / 逾期 → 归档。

- 顺延最多 3 次；第 3 次触发"拆分 / 降级 / 放弃"建议。
- 逾期 7 天自动进入"待清理"，询问用户。

**路线**：草稿 → 待确认 → 生效中 → 已完成 / 已暂停 / 已放弃 → 归档。

- 生效中可生成新版本；旧版本保留可对比。

**错题**：待复习 → 复习中 → 已掌握 → 归档；答错回退。

- 已掌握仍可被每月抽查。

## 6. 关键流程

### 6.1 首次上手（Onboarding）

1. 注册 / 登录。
2. 填目标：岗位、批次、截止日、每日可用时间。
3. 上传简历 → 解析 → 用户确认 / 修正。
4. 困境问卷（5–8 题）：薄弱项、最近一次被问倒的问题、最怕的环节、每天能投入多久、目前最卡的地方、目标公司层级、是否接受高强度。
5. AI 诊断：能力画像 + 差距 + 建议（先给 3 条可感知的洞察）。
6. 生成路线：阶段 / 周 / 日，带产出与验收。
7. 预览：强度 / 周期 / 侧重调整；局部重生成；查看"为什么"。
8. 确认：写入路线 + 首周 + 首日计划。
9. 绑定推送：企微 / QQ；发送测试消息。
10. 次日早报开始执行。

**异常**：简历解析失败 → 手动填关键字段；时间预算太少 → 推荐"最小可行路线"；目标过高 → 风险提示 + 替代方案。

### 6.2 每日闭环

1. 21:00 生成次日计划（或 07:00 生成当日）。
2. 07:30 早报推送。
3. 用户点开今日页 / 卡片；完成、跳过、顺延。
4. 练习提交 → 异步评分 → 结果通知。
5. 20:30 晚间复盘推送。
6. 用户完成 3 问复盘；系统汇总。
7. 错题入队；次日计划纳入 D+1 复习。
8. 周日晚周报 + 重规划建议。

### 6.3 练习 → 评分 → 错题 → 复习

1. 用户从今日任务进入练习。
2. 提交代码 / 文档 / 答案。
3. 系统做完整性校验（文件、语言、必填）。
4. AI 评分（异步，进度可见）。
5. 输出分数、维度、证据、改进、追问。
6. 未达标 / 答错 → 生成错题（含错误类型、知识点）。
7. 复习调度器计算下次到期日。
8. 到期进入日计划；复习结果更新 stage。
9. 掌握后归档；每月抽查。

### 6.4 路线生成 → 确认 → 入计划

1. 触发：onboarding / 平台跳转 / 用户主动 / 重规划。
2. 组装上下文：简历、困境、目标、时间、历史、错题。
3. AI 生成草案（JSON）。
4. 校验器：容量、依赖、产出、时长、日期。
5. 预览：阶段 / 周 / 日三级；容量热力；风险提示。
6. 用户调整：旋钮、局部重生成、手动改、锁定。
7. 确认：版本化落库；生成首周任务池。
8. 日编排器接管每日生成。
9. 后续：进度跟踪 → 触发重规划。

### 6.5 导入外部计划

1. 上传 / 粘贴 md、html、txt。
2. 格式识别 + 正文抽取。
3. AI 解析为统一 schema（阶段 / 周 / 任务 / 日期 / 时长 / 产出）。
4. 校验与冲突检测。
5. 预览树 / 日历；标红问题；手动修正。
6. 选择合并 / 替换 / 追加。
7. 落库（批次 ID）；生成日计划。
8. 可回滚。

### 6.6 平台联动

1. 用户在平台测评页点击"加入恒序计划"。
2. 跳转恒序，携带 intent、岗位 ID、测评 ID。

6. 完成项目后（P2）回写能力标签。

## 7. 关键规则与算法

### 7.1 每日编排

目标：在真实时间内，选出"今天最该做且做得到"的任务。

**输入池**

- 路线中 `scheduled_date ≤ 今天` 且未完成的任务
- 复习队列中 `due_date ≤ 今天` 的错题
- 周期计划今日实例
- 收集箱中用户标记"今天"的条目
- 昨日顺延任务
- 用户手动添加

**硬约束**

- 依赖满足
- 总时长 ≤ 日预算 × 80%（留 20% buffer）
- 任务数 3–6（可配置）
- 复习时长 ≤ 35%
- 每类型有上下限（如算法 1–3 题）
- 锁定项必选 / 必不选
- 任务颗粒度 15–90 分钟；超过 90 分钟拆分；小于 15 分钟合并
- 用最近 14 天完成率校准容量：完成率 < 70% 时按 0.8 折算

**打分**

```text
score(t) = 0.30 * goal_urgency(t)      # 截止日越近越高
         + 0.25 * review_decay(t)      # 复习 overdue 越久越高
         + 0.20 * stage_weight(t)      # 当前阶段重点
         + 0.10 * carry_pressure(t)    # 顺延 1-2 次加权；第 3 次转"待决策"
         + 0.10 * ability_gap(t)       # 画像薄弱项
         + 0.05 * variety_bonus(t)     # 类型多样性
```

**组装**

按分数贪心 + 背包约束；先保复习配额，再排新内容；最后插入 1 个"锚点任务"（最小可完成项，防止归零）。

**输出**

- 任务列表 + 顺序 + 预计时长
- "今日聚焦"一句话
- 每项"为什么今天做"（引用目标 / 错题 / 阶段）
- 对齐度预估

生成后用户可调；系统记录调整原因，用于偏好学习（P1）。

### 7.2 对齐度

先定义本周重点的目标时间分布，再比较实际分布。

```text
目标分布（本周重点）：项目 50% / 算法 30% / 八股 20%
实际分布（今日计划）：算法 70% / 项目 20% / 八股 10%

计划对齐度 = 1 - 0.5 * (|0.70-0.30| + |0.20-0.50| + |0.10-0.20|)
           = 1 - 0.5 * (0.40 + 0.30 + 0.10)
           = 60%
```

- 按预计时长计算**计划对齐度**；按实际时长计算**执行对齐度**。
- **完成率**回答"做没做"；**对齐度**回答"做的是不是重点"。两个一起看，避免"很努力但跑偏"。
- 对齐度只衡量一致性，不衡量目标本身是否合理；目标合理性由周复盘 / 重规划负责。
- 偏差 > 20% 时提示；连续 2 周偏差 > 20% 触发重规划建议。
- 周对齐度 = 一周执行对齐度的加权平均。

### 7.3 复习调度

默认节奏：学习后第 **1 / 3 / 7 / 14 / 30 / 60** 天复习。

实现上存"距上次复习的间隔"：`[1, 2, 4, 7, 16, 30]` 天；也支持"绝对天数模式"（1/3/7/14/30），适合不想算间隔的用户。

- 新错题：stage = 0，due = 次日。
- 答对：stage + 1；due = 今天 + 下一间隔；掌握度上升。
- 答错：stage = max(0, stage - 1)；due = 次日；lapses + 1；错误类型可更新。
- 连续答对 2 次可跳 1 阶（可选，P1）。
- stage 超过末位且连续 2 次答对 → 已掌握，归档；每月抽查 1 次。
- 每日配额：默认 `min(到期数, 10 题)`；同时复习时长 ≤ 日预算 35%。
- 积压：overdue > 7 天或到期 > 2 × 配额 → 只取高优（lapses 高、关联本周重点、近期到期）。
- 优先级：`overdue_days * 2 + lapses * 3 + stage_weight + goal_relevance`。
- 复习任务与普通任务同池编排，但若到期，至少保底 1 题。
- 变式：同一知识点生成新问法；连续答对后优先变式，防背题。

### 7.4 评分 rubric

**算法（100）**

| 维度 | 权重 | 看什么 |
|---|---|---|
| 正确性 | 35 | 样例、边界、异常、约束 |
| 复杂度 | 20 | 时间 / 空间分析与实现一致 |
| 代码质量 | 20 | 命名、结构、可读性、语言习惯 |
| 测试与验证 | 15 | 自测用例、对拍、断言 |
| 表达与复盘 | 10 | 思路说明、收获、可改进点 |

**工程化（100）**

| 维度 | 权重 | 看什么 |
|---|---|---|
| 问题与目标 | 15 | 背景、目标、范围是否清晰 |
| 方案与取舍 | 25 | 备选方案、权衡、边界 |
| 代码结构 | 20 | 抽象、分层、可维护 |
| 工程质量 | 20 | 测试、CI、文档、错误处理 |
| 结果与度量 | 10 | 效果、性能、数据 |
| 表达 | 10 | README、演示、复盘 |

**八股 / 项目口述（100）**

| 维度 | 权重 | 看什么 |
|---|---|---|
| 准确性 | 35 | 概念、原理是否正确 |
| 完整性 | 25 | 关键点是否覆盖 |
| 深度 | 20 | 原理、取舍、边界 |
| 结构与表达 | 10 | 先总后分、例子、时长 |
| 追问应对 | 10 | 追问下的稳定性 |

**结构化输出示例**

```json
{
  "score": 72,
  "level": "B-",
  "pass": false,
  "dimensions": {
    "correctness": 24,
    "complexity": 16,
    "quality": 15,
    "testing": 9,
    "communication": 8
  },
  "evidence": [
    {
      "quote": "self.capacity = capacity",
      "file": "lru.py",
      "line": 12,
      "comment": "未校验 capacity <= 0，后续 evict 可能异常"
    }
  ],
  "strengths": ["哈希表 + 双向链表结构正确"],

    {

### 7.5 重规划触发与策略

**触发**

- 周完成率 < 60%
- 连续 3 天完成率 < 50%
- 目标 / 截止日变更
- 阶段结束未达验收
- 新增大批错题（> 20 道/周）
- 用户主动

**策略**

- 保留已完成与锁定项
- 未完成按优先级重排，不简单顺延
- 降低强度或延长周期，二选一让用户选
- 生成差异说明（改了什么、为什么）
- 版本化，可回滚

### 7.6 防过载与保底

- 计划量 ≤ 80% 预算；留 buffer。
- 连续落后 → 自动降载 20%，并提示。
- 保底模式：只保留 1 个最小任务（1 题 / 1 复盘 / 1 口述）。
- 逾期 > 7 天 → 待清理，不无限堆积。
- 生病 / 加班 → 一键"今天休息"，任务自动重排，不扣累计记录（P1）。
- 激励展示"累计执行天数"而非"连续天数"，避免断签焦虑。

### 7.7 日期、时区与顺延

- 以用户时区为准；日界线默认 04:00（照顾熬夜），可配置。
- 日计划按 `(user_id, date)` 唯一；重生成覆盖未开始项，保留已完成。
- 顺延只改 `scheduled_date`，不改任务本身；记录次数。
- 跨周顺延进入下周池，优先级降一档。

### 7.8 幂等与一致性

- 日计划生成：同一用户同一天幂等；并发锁。
- 推送：`(user, date, type)` 幂等；失败重试不重复打扰。
- 评分：`submission_id` 唯一；重试不重复计分。
- 导入：批次 ID；重复导入提示。

## 8. 智能体设计

### 8.1 角色

| 角色 | 职责 | 触发 | 关键输出 |
|---|---|---|---|
| Planner | 诊断、路线、重规划 | onboarding / 周复盘 / 手动 | 路线 JSON + 解释 |
| Coach | 算法 / 工程评分 | 提交 | 评分 JSON + 改进 |
| Examiner | 出题、抽问、变式 | 每日定时 / 复习到期 | 题目 + 参考答案 + rubric |
| Reviewer | 日 / 周复盘 | 定时 / 用户 | 复盘文本 + 指标 |
| Importer | 外部计划解析 | 导入 | 统一 schema + 问题清单 |
| Librarian | 知识点 / 错题归因 | 评分后 / 复习后 | 知识点映射 + 错误类型 |

### 8.2 上下文与记忆

- **用户画像**：目标、时间、能力、偏好、历史反馈。
- **短期**：今日计划、最近 7 天表现、当前错题。
- **长期**：简历、路线、能力趋势、错题掌握、评分历史。
- **检索**：按知识点 / 项目 / 岗位召回相关材料，避免全量塞 prompt。
- **记忆写入**：评分结论、用户修正、偏好变化；带来源和时间。

### 8.3 工具

- 文件读取（简历 / 代码 / 文档）
- 代码静态分析、测试执行（可选，沙箱）
- 题库 / 知识点检索
- 计划 CRUD（受权限与校验器约束）
- 推送发送
- 统计查询

### 8.4 输出契约

- 所有结构化输出走 JSON Schema 校验；失败重试 1 次，再失败降级为"草稿 + 人工"。
- 评分 / 路线必须带 `confidence` 与 `evidence`。
- 计划类输出必须通过容量 / 依赖 / 日期校验器，校验不过不允许落库。

### 8.5 质量控制

- rubric 版本化；每次评分记录版本。
- 少量人工标注集，定期评估 AI 与人工一致性。
- 用户申诉 → 人工 / 强模型复核 → 回流样本。
- 禁止无证据的负面评价；不确定要明说。
- 计划质量看"采纳率 / 调整率 / 完成率"，不只看生成速度。
- AI 生成题目的参考答案需可追溯；用户可纠错，错误题目下架。

### 8.6 成本与延迟

- 轻任务（解析 / 分类 / 摘要）用小模型；重任务（路线 / 评分 / 复盘）用强模型。
- 简历解析、题目、知识点做缓存；相同输入不重复调用。
- 夜间批处理（日计划 / 周报）；交互路径异步 + 进度提示。
- 每日预算告警；超限降级（如评分改为轻量 rubric）。
- 本地 / 自带 Key 选项（P1）。

## 11. 集成与技术约束

### 11.1 企业微信

- **群机器人 webhook**：接入最快，适合早报 / 晚报；支持文本、markdown、图文等；有频率限制，需队列与限流。
- **自建应用**：可发应用消息、支持更强交互（按钮 / 回调），需要企业认证与配置，成本更高。
- **关键限制**：群机器人是**单向 webhook**，不能接收用户回复。因此 MVP 的"完成 / 跳过"必须走**签名链接回 Web**；消息内按钮 / 回复需自建应用或 QQ 机器人。
- 建议：MVP 用群机器人；P1 再上自建应用或 QQ。
- 注意：消息长度、markdown 语法差异、@ 成员、频率限制以官方文档为准。

### 11.2 QQ 机器人

- **官方 QQ 开放平台**：合规、稳定，但主动消息受限、需要审核。
- **OneBot / NapCat 等**：接入快、自由度高，但依赖个人号 / 框架，有风控与封号风险。
- 建议：P1 接入，作为企微的补充；优先官方渠道；做好降级。
- 注意：主动推送频率、群 / 私聊权限、内容审核。

### 11.3 求职平台联动

- **账号**：OAuth2 / OIDC 或一次性签名 token；避免共享密码。
- **深链**：携带 `intent`、岗位 ID、测评 ID、简历 ID；服务端换取短期上下文。
- **数据**：先做"读平台"（岗位 / 测评 / 简历），再做"写平台"（能力标签 / 项目）。
- **契约**：定义 `POST /api/integration/context` 与 `POST /api/integration/events`；版本化。
- **失败**：平台不可用时不阻塞恒序核心流程，使用本地缓存 / 手动填写。

### 11.4 本地代码采集（关键决策）

浏览器无法直接读本地目录，需选形态：

| 方案 | 体验 | 成本 | 隐私 | 建议 |
|---|---|---|---|---|
| 上传 zip / 单文件 | 手动，简单 | 低 | 可控 | MVP |
| Git 仓库 URL + OAuth | 自动拉取，适合工程 | 中 | 依赖平台 | P1 |
| CLI `persistlog submit` | 轻量，极客友好 | 中 | 可控 | P1 |
| 桌面端 / 本地 Agent 监听目录 | 最顺滑，可只传摘要 | 高 | 最好（本地初评） | P1/P2 |
| File System Access API | 浏览器授权目录 | 中 | 可控 | P2（兼容性差） |

建议：MVP 上传 + Git；P1 做 CLI + 桌面端；提供"只上传 diff / 摘要"的隐私模式。

### 11.5 AI 基建

- **模型**：支持多供应商路由；结构化输出；函数调用。
- **队列**：评分 / 路线 / 解析走异步任务；失败重试；死信队列。
- **沙箱**：代码执行需隔离（容器 / 资源限制 / 无网络）；默认关闭。
- **提示词**：版本化；评测集；回归测试。
- **数据**：脱敏后入 prompt；不把完整简历发给非必要模型。

## 12. 范围与里程碑

### 12.1 MVP（P0）

**目标**：验证"AI 路线 + 每日推送 + 练习评分 + 错题复习"能否让用户连续使用 14 天。

**包含**

- 账户、目标、时间预算
- 简历上传解析、困境问卷、能力画像
- AI 路线生成（预览 / 调整 / 确认）、手动 CRUD、周期计划
- 日计划自动生成、今日页、打卡 / 顺延 / 跳过、对齐度
- 企微群机器人早报 / 晚报 + 签名链接交互
- 算法提交 + AI 评分
- 工程化提交（文档 / zip）+ 评分
- 每日抽问 + AI 评估 + 错题本 + 1/3/7/14/30 复习 + 自动入计划
- md 导入 + AI 解析 + 预览
- 日复盘 + 基础统计

**不包含**：QQ、SSO、HTML 导入、本地目录监听、变式题、周报、能力雷达、语音、沙箱执行。

**验收**

- 新用户 10 分钟内完成配置并拿到首日计划
- 连续 7 天推送可达
- 评分有证据与改进
- 错题按计划出现
- 导入 md 成功率 ≥ 80%（结构化计划）

**粗略工作量**：单人全栈 + AI 辅助约 6–8 周，取决于本地代码接入深度。

### 12.2 P1

- HTML 导入、周报、能力雷达、趋势
- QQ 机器人、企微应用
- Git / CLI / 本地目录
- 重规划、版本对比、锁定
- 申诉 / 人工校准
- 平台 SSO + 深链 + 测评 / 简历读取
- 日历视图、导出、移动端适配

### 12.3 P2

- 平台数据双向同步、面试官联动
- 变式题、语音作答、沙箱执行
- 桌面端、本地模型
- 分享、模板市场、多人 / 社区
- 自适应难度、主动关怀

### 12.4 建议顺序

1. 先做"计划 + 每日 + 推送"——没有这个，其他都是空转。
2. 再做"提交 + 评分"——反馈闭环。
3. 再做"错题 + 复习"——记忆闭环。
4. 然后"导入 + 报告"——降低维护成本、展示价值。
5. 最后"联动 + 增强"——放大流量与体验。

### 12.5 关键验收场景

**AC-01 首次上手**

- Given 新用户只有一份简历 PDF 和每天 2 小时
- When 完成目标、简历、困境、时间配置并确认路线
- Then 10 分钟内生成首日计划（3–6 项，含产出与验收），并收到测试推送

**AC-02 算法练习闭环**

- Given 今日有算法任务
- When 提交代码与自测结果
- Then 30 秒内返回评分（维度、证据、≤ 3 条改进、追问）；未达标自动生成错题，次日出现在日计划

**AC-03 错题复习**

- Given 错题 stage = 0
- When 次日复习答对
- Then stage = 1，下次到期为 D+3；答错则回退并次日重现；复习记录可查

**AC-04 导入**

- Given 一份 markdown 学习计划
- When 上传并确认解析结果

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| AI 计划理想化、不可执行 | 用户放弃 | 容量约束、历史完成率校准、保底模式、重规划 |
| 评分主观 / 不可信 | 反馈闭环失效 | rubric、证据、置信度、人工校准、申诉 |
| AI 出题答案错误 | 学错知识 | 参考答案可追溯、多模型交叉、用户纠错、下架 |
| 用户坚持不下来 | 留存低 | 推送、最低限度、累计记录、周报正反馈 |
| 错题积压 | 压力大、放弃 | 配额、优先级、批量归档、只复习高优 |
| 本地代码隐私 | 不敢用 | 本地模式、只传摘要、明确授权、删除 |
| 企微 / QQ 限制 | 推送不稳定 | 多通道、降级站内、限流重试 |
| 双系统联动复杂 | 拖慢进度 | 先深链 / SSO，后数据同步；契约先行 |
| AI 成本失控 | 不可持续 | 分级模型、缓存、预算、批处理 |
| 计划频繁变更 | 用户困惑 | 版本化、差异说明、锁定、确认制 |
| 数据丢失 | 信任崩塌 | 备份、导出、审计 |

## 15. 待确认问题

> 以下问题会显著影响范围与架构，建议先拍板 1–6。

1. **产品形态**：只做 Web + 企微，还是需要桌面端 / 移动端？本地代码采集是否必须"自动监听目录"？
   - 建议：MVP 用 Web + 企微 + 上传；P1 做桌面端 / CLI。
2. **用户范围**：只自己用，还是要给其他人用（多租户 / SaaS）？
   - 建议：先单用户 / 小范围，按多用户设计数据模型，但不做运营后台。
3. **账号体系**：与求职平台是否统一账号？谁做 IdP？
   - 建议：平台做 IdP，恒序接 OAuth2 / OIDC；先做深链，后做 SSO。
4. **推送首选**：企微还是 QQ？是否有企业微信主体 / 群？
   - 建议：企微群机器人优先；QQ P1。
5. **AI 预算与模型**：每天可接受多少成本？是否自带 Key？是否允许代码 / 简历出境？
   - 建议：设每日预算；轻任务小模型；敏感数据脱敏；优先境内模型。
6. **评分风格**：严格（面试官视角）还是鼓励（教练视角）？是否需要"通过线"？
   - 建议：默认教练视角 + 明确通过线；可切换严格模式。
7. **每日时间**：用户手动填，还是从日历 / 历史推断？
   - 建议：手动填 + 每周校准；历史完成率自动修正。
8. **复习参数**：默认 1/3/7/14/30 是否合适？每日上限多少？
   - 建议：默认 10 题 / 35% 时长；可配置。
9. **计划导入格式**：除了 md / html，是否要支持 Notion / 飞书 / Excel？
   - 建议：先 md / html / 粘贴；Excel P2。
10. **数据保留**：简历 / 代码保留多久？是否允许用户彻底删除？
    - 建议：默认保留至用户删除；提供一键导出 / 删除。
11. **是否做社区 / 排行榜**：
    - 建议：不做，至少 MVP 不做。
12. **成功标准**：你个人用 2 周后，什么结果算"这产品成了"？
    - 建议：连续 14 天有执行 + 错题复习不掉队 + 能感到表达 / 算法有提升。

## 16. 附录

### 16.1 术语

| 术语 | 含义 |
|---|---|
| 路线 Roadmap | 从当前水平到目标岗位的阶段化计划 |
| 日计划 DailyPlan | 某一天的任务集合与聚焦说明 |
| 任务 Task | 最小执行单元，含产出与验收 |
| 提交 Submission | 一次练习的代码 / 文档 / 答案 |
| 评分 Evaluation | 对提交的结构化评估 |
| 错题 Mistake | 一次错误的结构化记录，含错误类型与知识点 |
| 复习 ReviewRecord | 一次错题复习的结果与下次到期 |
| 对齐度 | 任务与目标 / 重点的匹配程度 |
| 保底模式 | 低状态下只保留最小任务 |

### 16.2 枚举

- **任务类型**：algorithm, fundamentals, engineering, project, resume, apply, review, interview, reflection
- **错误类型**：concept, memory, boundary, complexity, structure, detail, misread, unknown
- **任务状态**：todo, doing, done, partial, skipped, deferred, overdue, archived
- **路线状态**：draft, pending_confirm, active, completed, paused, abandoned, archived
- **错题状态**：pending, reviewing, mastered, archived
- **推送类型**：morning, noon, evening, review_due, weekly, roadmap_update, alert

### 16.3 推送文案示例

**早报**

【恒序 · 今日】10/20 周二 · 距目标还有 38 天
本周重点：项目表达（40%）｜算法（35%）｜八股（25%）

1. [算法] 滑动窗口 2 题 · 45min
   产出：代码 + 复杂度注释
2. [复习] 昨日错题 3 道（HTTP 缓存 / 索引失效 / 三次握手）· 20min
3. [项目] 订单系统：补架构图与取舍说明 · 60min

预计 2h05m｜完成 2/3 即达标
点开详情调整或标记完成。
```

**晚报**

```text
【恒序 · 复盘】今日完成 2/3，对齐度 78%
算法 72 分（边界遗漏）｜新增错题 2｜明日复习 3
一句话：今天最大的卡点是什么？
```

**周报**

```text
【恒序 · 周报】第 6 周
完成率 68%｜对齐度 74%｜有效执行 4 天

下周重点：项目表达 + 模拟面试 2 次

```

### 16.4 参考方法

- 间隔重复（Spaced Repetition）与 SM-2 的简化变体
- 刻意练习（Deliberate Practice）：明确目标、即时反馈、走出舒适区
- 逆向规划（Backward Planning）：从截止日倒推阶段
- 掌握学习（Mastery Learning）：通过线 + 复习直到掌握

### 16.5 本版假设

- 用户为计算机专业求职者，中文环境，主要目标为校招 / 社招技术岗。
- 首版单用户 / 小范围使用，不做复杂权限与运营。
- AI 评分是辅助而非裁决，最终以用户判断为准。
- 求职平台可提供岗位 / 测评 / 简历数据，或至少可深链。
