## 0. 结论

按项目设计，现在处于 **Phase 1 的“后端完成、前端初步联调”阶段**：

- Phase 1 后端 M1–M8 + W0 已完成，API 可联调。

**下一步不是 Phase 2，而是把 Phase 1 做成可真实使用的产品**：先补 B-01/B-10 两个前端前置项并启动前端，7 周左右完成前端 MVP，再用 1–2 周 dogfood + 上线硬化，最后做 Phase 1 退出评审。

## 4. Phase 2：代码静态评审（方案 A）

### 4.1 进入条件

- Phase 1 退出条件全部满足。
- 明确代码提交格式（文件/粘贴、语言、题目、自测、复杂度、独立性、思路）。
- 确认“不判 AC、只做静态风险”的产品口径。
- Rubric 维度与权重定稿。

### 4.2 范围

- 网页提交/粘贴代码；**不执行代码、无沙箱、无 CLI/Git/IDE**。
- AI 只读代码和提交信息；正确性只给“静态风险 + 自测通过率”。
- 输出：总分/等级/置信度、维度分、证据（文件/行号/片段）、优点、≤3 条改进、1–3 个追问、`not_evaluated`。
- 评分趋势：最近 30 天、提交次数、平均分、最高分、维度趋势、自测通过率、改进项完成率。

### 4.3 任务拆分

| ID | 任务 | 预估 | 验收 |
|---|---|---|---|
| P2-01 | 增量迁移：practice_sessions、code_submissions、evaluations、rubrics、rubric_versions | 1 天 | upgrade/downgrade 可执行；索引/唯一约束齐全 |
| P2-02 | 练习/提交 API | 2 天 | 创建会话、提交代码、语言/题目/自测/复杂度/独立性/思路 |
| P2-03 | AI 评审流水线 + Rubric + Schema 校验 | 3 天 | 60s 内返回结构化评审；失败保留提交可重试；记录 ai_runs/rubric_version |
| P2-04 | 评审查询/历史/趋势 API | 2 天 | 一个 submission 多次评审只有一条 is_current；趋势可查 |
| P2-05 | 前端练习历史、评审结果、看板算法区块 | 4 天 | 证据可定位行；改进项可勾选；追问展示 |
| P2-06 | 10 份代码样本回归 + 安全/硬化 | 3 天 | 证据定位抽检通过；`not_evaluated` 语义正确 |

合计约 **15 人日 ≈ 3 周**，加缓冲 4 周。

### 4.4 验收（01 §5.2）

- 算法任务可提交代码 + 语言/题目/难度/自测/复杂度/独立性/思路。
- 60 秒内返回结构化评审：总分、维度、证据、优点、≤3 改进、追问、置信度。
- 每条问题有文件/行号证据；无证据标 `not_evaluated`。
- 正确性显示为“静态风险 + 自测通过率”，不显示 AC/正确。
- 评审结果可查看/重新提交/对比。
- 看板显示评分趋势、提交次数、平均分、维度趋势。
- 没有沙箱、没有代码执行、没有 CLI/Git/IDE。
- 用户可标记改进项完成；趋势能反映。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Redis/企微/AI 外部依赖不可用 | 联调/上线延期 | 先用 Stub/Logging 开发；把真实链路拆成独立验收项；提供降级路径 |
| Cookie 跨域/同源配置错误 | 登录态丢失、刷新失败 | 优先同源反代；固定 host；CORS 白名单 + `credentials: include`；联调清单覆盖 |
| 认证契约变更 | 前端返工 | W0 后冻结；`05` + `openapi.json` 为准；变更必须同步文档和类型 |
| 时间戳/时区处理错误 | 今日/顺延错天 | 统一 `YYYY-MM-DD`；时间戳按 UTC；B-10 补 `Z`；跨时区测试 |
| 看板口径不一致 | 用户不信任 | 指标定义 + 对账测试；前端不自行计算完成率 |
| 导入格式差异 | 导入成功率低 | 规则 + AI + 预览编辑；先支持模板；问题清单可操作 |
| 范围蔓延 | Phase 1 延期 | 严格按 01 §5.1；Phase 2/3 不提前；P1/P2 任务不阻塞 MVP |
| 单人排期过紧 | 质量下降 | 7 周前端 + 2 周缓冲；先保 F-02/F-04；可裁剪 F-05 图表精细度 |
| 安全（XSS/CSRF/SSRF） | 账号/数据风险 | access token 内存；HttpOnly Cookie；Origin 校验；Webhook 白名单；依赖审计 |
| 数据丢失/误回滚 | 用户数据损失 | 回滚前置检查；每日备份；生产恢复演练 |
| 指标造假/空数据 | 产品信任受损 | 无证据显示“未评估”；空态明确；不显示假分数 |
