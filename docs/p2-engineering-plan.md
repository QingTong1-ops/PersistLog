## 3. 工程方案

### 3.1 分层与拟新增文件

```text
app/(app)/practice/page.tsx
app/(app)/practice/new/page.tsx
app/(app)/practice/[id]/page.tsx
components/practice/
  practice-view.tsx / submission-form.tsx / review-view.tsx
  submission-history.tsx / code-snapshot.tsx / review-progress.tsx
  review-result.tsx / review-attempts.tsx / review-followups.tsx
  practice.module.css
components/dashboard/code-dashboard-section.tsx
components/async-task/                 # P2 建立，P3 按需复用
lib/api/practice.ts                    # 只封装已确认的真实端点
lib/types/practice.ts                  # 与 DTO/展示模型明确区分
lib/hooks/use-async-task.ts
tests/unit/、tests/e2e/                 # 首次引入测试工具时创建
```

文件名为建议拆分，不要求为凑目录创建空文件。页面入口负责 metadata、参数；Client 视图负责表单和交互；API 模块复用 `lib/api/client.ts`。不把全部 P2 数据塞入 P1 的 `AppStoreProvider`。

沿用 `PageHeader`、`Button`、`Tag`、`ProgressBar`、`Modal`、`Sheet` 等共享组件；领域状态不可强塞进现有只接受 P1 任务状态的 `StatusBadge`。新页面私有样式使用 CSS Modules，引用当前 optimized token，不直接加载原型全局 CSS，不修改 `.app` 布局。

### 3.2 数据、缓存与异步

- 首版优先现有 API 客户端 + 领域 hook，不以全站引入缓存库为前置条件。需要新依赖时在对应任务说明用途并限定范围。
- 提交、评审、任务是不同对象；任务执行状态与“已评分/证据不足”分别建模。
- 真实进度由后端查询驱动；默认轮询，频率与重试上限待契约确定。SSE 是后端已交付时的可选替代，不作为首版依赖。
- 切换提交/评审、离页、登出时取消旧请求与轮询；防止迟到响应覆盖新页面。终态停止轮询，后台标签页降频/暂停，重新可见时拉取最新状态。
- 网络查询失败不等于评审失败；提供手动刷新，保留代码和最后一次有效状态。没有百分比时显示处理阶段，不补假进度。
- 相同写操作重试复用同一幂等键；用户主动新建一次评审使用新键。超时结果未知时先查询，不盲目重复提交。
- 草稿/改进项使用服务端版本处理冲突；正式快照只读，修改生成新草稿/提交，重评只新增评审记录。
- 代码和回答不默认进入 localStorage/sessionStorage；草稿以服务端为准。仅过程摘要展开偏好可按用户/提交/评审保存至会话存储，不保存业务进度或评分。
- 改进保存后更新对应列表、详情和代码统计；写失败回滚 UI，不能只 Toast“成功”。

### 3.3 后端未就绪时的实施边界

计划批准后可先完成类型草案、纯展示组件和测试夹具。夹具用于 `dev:mock/build:mock` 演示模式或独立测试，必须标注“演示”；不能在真实接口错误时自动回退为示例。模拟写入/异步状态由领域 Mock 适配器提供，不在页面内分叉实现。后端未就绪不阻塞 Mock 页面验收，但阻塞真实联调完成标记。

未交付真实端点的任务标记为“页面完成 / 待联调”，不开通真实用户写入口，不对外声称已支持。未约定的字段和 URL 不写成假定已存在的接口。

## 5. 关键验收要求

### 5.1 表单、评分与权限

- 代码文本上限按需求文档采用 **200 KiB（204800 字节）**；原型“200 KB”文案需统一，字节计数用实际文本编码，不用 JS 字符长度代替。文件读取不执行代码，读取失败保留旧输入。
- 语言候选为 Python 3.11、Java 17、JavaScript、TypeScript，最终合法集合/扩展名以契约为准。选择文件替换已有编辑内容前明确确认。
- 已自测：总数为正整数，通过数为非负整数且不大于总数；未自测：相关字段为空，不提交残留数值。
- 正式授权不照搬原型预勾选；分别解释代码读取范围、AI 处理用途、保留政策，未授权只保留输入。
- 总分、等级、置信度、维度与统计来自后端。示例 `76 / B+ / 0.82` 仅在测试夹具中出现，不能作为默认值或反推算法。
- 待评审、失败、证据不足不计入均分/最高分。最新失败不能展示旧成功评分为最新；历史结果可单独查看。
- 无权限、不存在、限流、授权撤回、资源版本冲突均有明确状态；不能把权限失败解释为“没有提交”。登出/换用户后清空页面私有缓存。

### 5.2 视觉与交互

- 桌面评审页左代码、右核心结果及依据，顶底对齐；增加的高度用于代码滚动，不空拉长卡片。`≤1100px` 单列。
- 评审中过程摘要默认展开，结束默认收起；用户手动选择优先，刷新后恢复 UI 偏好，不恢复模拟任务状态。
- 代码长行只在代码区域滚动；行号证据点击定位并有键盘入口；长标题、200 KiB 文件、多次历史、零记录不撑破主区。
- 必测 `1280×720`、`584×761`；补测 `1440×900`、`390×844` 以及 1100/860/640/420 断点附近。记录实测，不以 CSS 断点存在代替通过。
- 固定侧栏可独立滚动，主文档负责正文滚动；禁止恢复根 `.app` 两列网格或用隐藏溢出掩盖压缩。
- 新抽屉/确认框检查 Tab、焦点陷阱/恢复、Esc、标题关联、背景交互和锁滚动；检查 reduced-motion；移动触控≥44px。

### 5.3 测试与交付证据

建议新增 Vitest + React Testing Library 与 Playwright（P2-02 引入并锁定依赖），测试夹具/请求拦截与生产路径隔离：

1. 单元：字节/字段校验、DTO 空值、状态展示、轮询停止/取消、幂等键生命周期、证据行范围。
2. 组件：五种评审状态、历史与最新隔离、服务端字段错误、冲突保留输入、图表缺失点、移动导航。
3. 浏览器：登录→关联任务→草稿→提交→离页/刷新→结果→证据→改进/追问保存→重评历史→7/30 天看板。
4. 异常：未自测、过期会话、断网/超时、重复提交、AI 失败重试、旧版本写入、越权 ID；后端权限和幂等需要真实联调，不以 mock 测试替代。
5. P1 回归：`/`、`/login` 留在登录注册入口；成功登录后的主流程、今日动作、路线/导入、既有看板/设置不退化。
6. 顺序执行 lint、build、typecheck、新增测试、`git diff --check`；build 与 typecheck 不并行，避免 `.next/types` 生成竞争。记录工具版本、视口、截图和实际结果。
