## 0. 结论

P2/P3 不是在现有 P1 上加几个接口，而是新增两套完整领域：

- **P2 代码反馈**：不可变代码快照、异步静态评审、评分/证据/改进/追问、代码趋势。
- **P3 反馈与记忆**：AI 诊断与路线草案、每日文字提问、错题与间隔复习、能力证据与准备度、复习设置。
- 另有平台固定入口、P1 今日容量联动等外围能力。

按当前前端需求的细度，单人后端预计 **14–16 周**（比早期 9–12 周估算多 3–4 周），主要增量在：**AI Harness 质量门禁**、幂等/版本冲突、异步任务步骤与恢复、证据追溯、复习调度和时区边界。前端可在每个里程碑后并行接入，不需要等全部完成。

**建议执行顺序**：M0 通用基础 → M0 AI Harness → P2 → P3 路线 → P3 提问 → P3 错题复习 → P3 能力 → 联调硬化。  
**当前进度**：M0.1/M0.2 已提交；P2 M1 已实现（157 tests），等待审查后进入 P2 M2。

- 复习默认节奏采用 `[2, 3, 7, 14, 28]` 天（旧技术设计中的 `[1, 4, 7, 14]` 是另一种口径）。
- 任务/步骤/重试/版本按前端需求补齐，不沿用旧的最小 `jobs` 字段。

## 2. 范围与不做

### 2.1 P2 范围

1. 代码草稿、代码快照、提交历史、提交详情。
2. 异步评审、进度、结果、失败重试、评审历史。
3. 评分、维度、代码证据、扣分依据、改进项、复盘追问。
4. 改进项完成状态、追问回答持久化。
5. 近 7/30 天提交、评分、自测、改进统计。
6. 从 P1 今日任务/路线任务进入代码提交；提交不自动完成 P1 任务。

### 2.2 P3 范围

1. 背景诊断、路线草案、容量预览、阶段锁定、局部调整、用户确认。
2. 每日 3–5 道文字题、回答、反馈、追问、会话恢复、错题生成。
3. 错题库、到期复习、三种掌握结果、间隔重复、每日配额与容量。
4. 复习设置读取/预览/保存/恢复默认。
5. 能力目录、路线权重、证据、评估、准备度、覆盖率、来源追溯。
6. 平台固定入口链接（只跳转，不传用户数据）。
7. 复习占用与 P1 今日计划使用同一容量口径。

### 2.3 明确不做

- 不执行代码、不做沙箱、不做 AC 判定、不跑隐藏测试、不测真实运行时间/内存。
- 不接 CLI、Git、IDE、求职平台账户、SSO、数据同步。
- 不做语音作答。
- 不向前端返回逐字思维链。
- 不让 AI 直接改执行中路线、覆盖历史完成记录或直接把代码分当能力分。
- 本轮不默认做：周报 HTML、管理后台、数据导出、账号删除、平台状态回传。若需要，单独立项。

## 3. 设计原则

1. **契约先行**：每个里程碑先定 OpenAPI、状态机和错误码，再写实现；前端不根据原型数据推断字段。
2. **服务端计算**：评分、容量、复习阶段、到期日、准备度、覆盖率全部后端算，前端只展示。
3. **不可变快照**：代码提交、评审结果、回答版本、证据来源版本不被后续编辑覆盖；修改产生新记录。
4. **用户隔离**：所有查询按 `user_id` 过滤；从 P1 任务进入时校验 task/stage/route 归属。
5. **异步可恢复**：用户内容先持久化，AI 任务可查询、可重试、可恢复，不长期卡在“处理中”。
6. **AI 分用途授权**：代码评审、路线生成、回答反馈分别授权；未授权不发送第三方。
7. **无证据不下结论**：没有自测不给正确性分/总分；证据不足/未评估不写 0；不伪造百分比和思考过程。
8. **复用 P1**：任务、今日计划、路线、看板、通知、审计、限流不另起一套。
9. **AI Harness 是硬门禁**：所有 AI 输出必须经过 Schema、证据/来源、业务规则、质量评分四层校验；低于阈值不进入正式结果；每个任务有黄金评测集和回归指标。详见 [AI Harness 设计](08-AI-Harness设计.md)。

**复用现有表**：

## 5. 数据模型与迁移

建议拆成 5 个增量迁移，避免一次大迁移不可回滚：

| 迁移 | 表 |
|---|---|
| `0002_common_foundation` | `idempotency_records`；`jobs` 增加 `stage/steps_json/attempt/max_attempts/retryable/started_at/finished_at/result_version/idempotency_key`；`ai_runs` 增加 `schema_version/consent_scope/validation_json/quality_score/quality_json` |
| `0003_p2_practice` | `code_drafts`、`code_submissions`、`code_evaluations`、`code_improvements`、`code_followups`、`rubric_versions` |
| `0004_p3_route_generation` | `route_generation_requests`、`route_diagnoses`、`route_drafts`、`route_draft_versions`、`route_draft_stages`、`route_draft_weeks`、`route_draft_tasks`、`route_draft_adjustments` |
| `0005_p3_quiz_review` | `quiz_sessions`、`quiz_questions`、`quiz_answers`、`quiz_feedback`、`quiz_followups`、`mistakes`、`review_settings`、`review_sessions`、`review_session_items`、`review_attempts`、`knowledge_points`、`mistake_knowledge_points` |
| `0006_p3_capability` | `capability_definitions`、`job_capability_requirements`、`capability_evidence`、`capability_assessments`、`capability_snapshots` |

关键约束：

- 代码提交：`user_id + code_hash + idempotency_key` 可查重；提交后代码/自测/复杂度/题目上下文不可更新。
- 评审：`submission_id + sequence_no` 唯一；只有一条 `is_current=1`；旧评审不覆盖。
- 草稿/路线草案/回答/复习设置：带 `version`；更新版本不匹配返回 `409 VERSION_CONFLICT`。
- 评审证据：文件名/行号/片段必须属于本次快照；服务端校验行号和片段。
- 错题：同一 `source_type + source_id + answer_version` 去重；原始回答与复习回答分表/分字段。
- 复习结果：同一 `review_session_item + answer_version` 幂等；重复提交不推进阶段。
- 能力证据：`source_type + source_id + source_version + capability_id` 唯一，重复消费不重复计数。
- 所有新表带 `created_at/updated_at`；用户私有数据用 `user_id` 外键和索引。

## 6. M0 通用基础与 AI Harness（2–2.5 周）

**目标**：让 P2/P3 可以安全地重复提交、版本更新、异步执行、分页和追溯，并让所有 AI 输出经过统一质量门禁。

### M0.1 数据/契约基础（1–1.5 周）

**状态：已完成（2026-11-20）**：迁移 0002、幂等中间件/记录、分页 envelope、版本冲突工具、Job 查询扩展；133 tests 通过。

### 交付

1. **统一分页/排序**：新接口返回 `{items, total, limit, offset}`；`total` 与筛选条件同源；稳定排序 `created_at desc, id desc`。
2. **幂等键**：`Idempotency-Key` + `idempotency_records`；同 key 同请求回放首次响应，同 key 不同 payload 返回 `IDEMPOTENCY_CONFLICT`；TTL 24h。
3. **资源版本**：草稿、路线草案、回答、复习设置返回 `version`；`If-Match` 或 body `version`，冲突 409。
4. **错误扩展**：`retryable`、`VERSION_CONFLICT`、`IDEMPOTENCY_CONFLICT`、`AI_UNAVAILABLE`、`AI_CONSENT_REQUIRED`、`QUOTA_EXCEEDED`。
5. **异步任务**：扩展 `jobs`；状态 `queued/running/succeeded/failed`；`stage`、`steps_json`、`attempt/max_attempts/retryable`、`result_version`；`GET /jobs/{id}` 返回步骤；worker 启动/beat 定时回收超时 running 任务。
6. **授权**：新增三种 AI scope；通用 `require_consent(scope)`；每个 AI 入口校验。
7. **测试与契约**：并发/幂等/分页/版本冲突/任务失败恢复测试；OpenAPI 骨架。

### 完成标准

- 不改变 P1 现有数组响应；新接口全部使用新契约。
- 同一请求重发不会创建第二条提交/评审/错题。
- 失败任务可重试，输入不丢；没有伪造进度。
- `alembic upgrade/downgrade` 通过。

### M0.2 AI Harness（1–1.5 周）

**状态：已实现（2026-11-20），待审查**：AITaskSpec、AIGateway、质量评分、通用 JSON Provider、业务校验器接口、EvalCase 骨架；150 tests 通过。

详细设计见 [08-AI-Harness设计](08-AI-Harness设计.md)。

**交付**：

1. `AITaskSpec` 注册表：任务类型、prompt/schema 版本、输出模型、证据规则、业务规则、质量权重、授权 scope、超时/重试。
2. `AIGateway`：授权/配额/预算检查 → provider 调用 → Schema 校验 → grounding 校验 → 业务规则校验 → 质量评分 → `ai_runs` 持久化。
3. 通用校验器：JSON Schema、代码证据行号/片段、来源引用、数值/容量/日期一致性、禁止项（AC/隐藏测试/实测性能/思维链）。
4. 质量评分：`schema_valid / grounding / completeness / consistency / safety` 加权；低分阈值与 `needs_review/failed` 处理。
5. 离线评测骨架：`tests/ai_evals/` 固定样本 + `scripts/eval_ai.py`；先覆盖代码评审/路线/反馈三类任务的 Schema、禁止项、约束。
6. 测试：非法 JSON、证据行号错误、编造引用、低质量、提示注入、超时/重试、低分不写正式结果。

**完成标准**：

- 任一 AI 任务不通过 harness 就不能写正式评分/证据/路线。
- 评测脚本可本地跑通；指标低于阈值时明确失败。
- 不将完整代码/简历/回答写入普通日志或 `ai_runs` 输入快照。

## 8. P2 明细

### M1 草稿与提交

**状态：已实现（2026-11-21），待审查；157 tests。**

- 表：`code_drafts`、`code_submissions`（迁移 `0003_p2_practice`）。
- 能力：保存/读取/删除草稿；从旧提交复制；提交并生成不可变快照。
- 校验：语言白名单（Python 3.11/Java 17/JS/TS）、200 KiB、文件名/扩展名、空代码/空题目、标签数量、自测通过数 ≤ 总数、未自测不填伪造计数、复杂度必填、独立性确认、代码评审授权。
- 接口：`/practice/context`、`/practice/drafts*`、`/practice/submissions*`、`/practice/submissions/{id}/copy-to-draft`。
- 返回：提交 id、行数、hash、创建时间；`review_status=not_started` 等 M2 接评审。
- 不做：提交时自动完成 P1 任务；M1 不创建评审任务。

### M2 异步评审

- 表：`code_evaluations`（含 `status/sequence_no/is_current/score/level/confidence/static_risk/dimensions_json/evidence_json/strengths_json/process_steps_json/rubric_version/ai_run_id`）。
- 流程：持久化提交 → 创建 job → Celery 读取快照 → AI 评审 → 校验证据/行号 → 写 evaluation → 更新 job/current。
- 状态：`queued/running/succeeded/failed/not_evaluated`；失败保留快照和步骤，允许重试；重试追加 evaluation，不覆盖旧结果。
- 约束：同一提交最多一个运行中评审；旧成功分不被最新失败覆盖为“最新分”。
- 未自测：正确性只给静态风险，正确性分/总分/等级为空；测试维度可 `not_evaluated`。

### M3 结果、改进、追问、趋势

- `code_improvements`：≤3 条，含 action/how/verify/evidence/status；用户主动完成，可关联后续提交；版本冲突。
- `code_followups`：问题/上下文/回答/版本；旧评审回答隔离。
- 趋势：`GET /dashboard/code-trends?days=7|30`；提交数按提交时间，平均/最高分按最新成功评审，自测通过率仅统计提供自测的提交，改进按持久化状态。
- 代码练习概览、提交历史筛选、其他提交历史。
- 空数据/空点不补 0。

## 9. P3 明细

### M4 诊断与路线草案

- 表：生成请求、诊断、草案、草案版本、阶段/周/任务、调整记录。
- 输入：目标岗位/日期、每日分钟、周期、简历/项目摘要、困境、路线 AI 授权；先保存用户输入。
- 流程：请求 → 异步诊断/生成 → 草案 v1 → 预览容量 → 调整/锁定 → 校验 → 用户确认 → 创建**路线草稿**。
- 容量：`周期天数 × 每日分钟 × 80%`；任务分钟求和；超容量禁止确认；目标日期冲突明确提示。
- 版本：每次调整新版本；锁定阶段不被局部调整改写；旧版本冲突 409。
- 确认：只建 `routes.status='draft'`，不自动激活，不覆盖现有路线。
- AI 失败：保留输入，任务 failed，可重试；不生成假草案。

### M5 每日提问

- 表：会话、题目、回答、反馈、追问；按业务日期恢复同一会话。
- 默认 4 题（3–5），来源：今日任务、错题、简历/项目、目标/低分能力；题目带来源类型/id/能力。
- 回答草稿/提交、反馈（准确性/完整性/深度/结构/追问）、追问最多 2 轮、计时暂停/恢复。
- 低分/答错生成错题，按来源去重；原始回答不被复习回答覆盖。
- AI 失败：回答已保存，反馈 failed/retry，不伪造反馈。

### M6 错题与复习

- 表：错题、知识点、复习设置、复习会话、会话项、复习记录。
- 默认：`[2,3,7,14,28]` 天、每日 10 题、35% 容量、到期优先；答错回退一级且次日重现；不确定保持；确定进阶；最后阶段进入 mastered/长期抽查。
- 每日配额：`min(到期数, 10, floor(容量×35%/每题分钟))`；超额顺延并返回原因；答错次日优先预留。
- 与 P1 今日联动：只为本次选中的复习题创建 `tasks.source_type='review'` + occurrence + daily_plan_item；完成复习回写 occurrence，容量进入今日统计。
- 设置：读取/预览/保存/恢复默认；间隔 1–365 严格递增；配置版本；已有阶段 clamp 并返回影响；不重置历史。
- 幂等/并发：同一题同一答案版本只推进一次；多标签页/旧版本冲突。

### M7 能力与证据

- 表：11 项能力目录、路线能力权重、证据、评估/快照。
- 证据来源：代码评审（仅成功评分）、提问反馈、P1 工程任务完成（有产出/备注）、自评、外部测评。
- 公式（建议默认，待确认）：有效权重 = 基础权重 × `0.5^(年龄天数/30)`；能力分 = 有效权重加权平均；置信度 = `min(1, 有效证据数/5)`；≥3 条且 ≥0.5 才 assessed；准备度只汇总 assessed 的路线权重；覆盖率按路线权重。
- 未评估返回空分数 + 原因；不进入准备度；不写 0。
- 证据可追溯到来源版本；撤回授权/删除来源时标记失效并重算。
- 代码/回答/任务完成后触发幂等重算；重复消费不重复计数。
- 端点：`/dashboard/capabilities`、`/capabilities/{code}`、证据列表/来源、自评/外部、重新评估。
- 平台入口：`GET /integrations/entry-links`，固定 URL，无用户数据。

## 11. 需要确认的规则（建议默认）

这些规则无法仅靠原型确定；若没有异议，按“建议默认”执行，并写入 OpenAPI/领域文档。

| # | 主题 | 建议默认 |
|---|---|---|
| 1 | 代码评分 | Rubric v1 固定权重 35/20/20/15/10；未自测不给正确性分/总分/等级；等级区间 A+≥95、A≥85、B+≥75、B≥65、C+≥55、C≥45、D<45；静态风险低/中/高 |
| 2 | 代码趋势归属 | 提交数按提交时间；平均/最高分按最新成功评审完成时间；自测通过率按提交且按用例加权；改进分母按创建时间、完成按完成时间 |
| 3 | 草稿保留 | 每人最多 20 份、30 天；提交后草稿保留 7 天再清理；正式提交不可删 |
| 4 | 每日提问 | 默认 4 题；来源配比 40% 今日任务 / 20% 错题 / 20% 简历项目 / 20% 目标能力；低于 60 分生成错题；追问最多 2 轮；默认计时 10 分钟 |
| 5 | 复习最后阶段 | 阶段 0–4；答错回退一级且次日重现；不确定保持；确定进阶；阶段 4 后再进阶为 mastered，60 天后抽查，连续 3 次 mastered 可归档；设置变更时阶段 clamp 到新末级，历史记录保留 |
| 6 | 路线生成 | 周期 4–24 周；每日 30–480 分钟；有效容量 80%；强度 low/standard/high 只影响任务密度，不允许突破容量；草案最多 10 版、30 天；确认只建路线草稿 |
| 7 | 能力置信度/工程证据 | 置信度 `min(1, 有效证据数/5)`；代码证据用评审总分，提问用反馈总分；工程任务仅在完成时填写产出/备注才生成证据；自评/外部测评标记“未经平台核验”；提交/题目需显式 `capability_codes`（默认继承 P1 任务标签） |

## 12. 测试与质量门禁

每个里程碑必须同时交付：

- 单元/服务/API 测试；P1 回归测试保持通过。
- 用户隔离、越权、跨用户列表/详情/统计测试。
- 幂等重发、重复点击、并发两个标签页、版本冲突。
- AI 失败/超时/非法 JSON/证据行号无效/重试恢复。
- 时区/日界线/跨日/夏令时（至少固定时区用例）。
- 迁移 `upgrade/downgrade`，种子幂等。
- OpenAPI 重新导出，前端生成类型不报错。
- 不记录完整代码/简历/回答到普通日志；`ai_runs` 只留 hash/摘要/输出。
- AI 任务必须跑对应评测集：Schema、grounding、业务约束、禁止项、低质量拦截。

**建议门禁**：每个 M 完成后跑 `pytest -q`、`ruff check`、`alembic upgrade head`、OpenAPI 导出、`scripts/eval_ai.py`；P1 关键 E2E 不回归。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 需求细、范围大 | 延期 | 按 M0–M8 分界；每期可独立联调；外围功能明确延后 |
| 评分/能力规则未定 | 返工 | 第 11 节先确认默认；规则版本化，后续可迁移 |
| AI 输出不稳定 | 评审不可用 | JSON Schema + 修复一次 + 证据/行号校验；失败保留输入可重试，不造假 |
| 复习调度复杂 | 阶段/到期错 | 纯函数调度器 + 固定用例/时区测试；配置版本写入记录 |
| 与 P1 今日容量冲突 | 两套分钟账 | 复习题物化为 `tasks.source_type='review'`，复用 daily plan/occurrence |
| 幂等/并发遗漏 | 重复提交/错题 | M0 统一幂等与版本；每个写接口加测试 |
| AI 成本/隐私 | 不可持续/泄露 | 分用途授权、每日配额、输入截断/脱敏、不存全文日志 |
| 前端契约变化 | 联调返工 | 每个里程碑 OpenAPI 评审后再进入下一里程碑 |
