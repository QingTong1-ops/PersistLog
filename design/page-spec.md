## 0. 全局约定

### 0.1 技术基线

- React + TypeScript + Next.js（遵循 `docs/02-技术设计.md`）。
- 设计 token 直接迁移 `prototype.css` 顶部变量。
- Access Token 只放内存；Refresh Token 依赖 HttpOnly Cookie，前端不写 localStorage。
- 所有接口带 `Authorization: Bearer <access_token>`；刷新失败跳转 `/login`。
- 时间统一按用户时区（默认 `Asia/Shanghai`）和日界线（默认 04:00）计算。
- 数字使用 `font-variant-numeric: tabular-nums`；日期统一 `YYYY-MM-DD`，展示为 `M/D` 或 `M 月 D 日`。

### 0.2 全局布局

- 桌面：252px 侧边栏 + 主内容（最大 1360px，左右 32px）。
- 顶栏：面包屑、日期、原型导航（仅原型）、通知、头像。
- 移动：隐藏侧边栏；顶部品牌 + 原型导航 + 头像；底部 4 个入口（今日/看板/路线/我的）。
- 登录和引导使用独立全屏布局，隐藏侧边栏、顶栏和底部导航。
- 原型导航只在设计稿中出现，正式版删除；它列出全部页面和状态演示。

### 0.3 路由

| 路由 | 页面 | 渲染条件 |
| --- | --- | --- |
| `/login` | 登录/注册 | 未登录 |
| `/onboarding` | 首次引导 | 已登录但未完成引导 |
| `/today` | 今日 | 默认首页 |
| `/import` | 导入计划 | 已登录 |
| `/routes` | 路线列表 | 已登录 |
| `/routes/{id}` | 路线详情 | 路线属于当前用户 |
| `/dashboard` | 执行看板 | 已登录 |
| `/settings/profile` | 档案与容量 | 已登录 |
| `/settings/notifications` | 企业微信推送 | 已登录 |
| `/settings/ai` | AI 授权 | 已登录 |
| `/settings/data` | 数据与账号 | 已登录 |

`#/` 在原型中使用哈希路由；正式版使用 Next.js 文件路由。

## 1. 登录 / 注册 `/login`

### 1.1 目标

让用户用邮箱或手机号 + 密码登录；首次用户可注册并进入引导。

### 1.2 结构

- 左侧品牌叙事（深墨蓝）：主张、三条价值点、3 个数字。
- 右侧表单卡：
  - Tabs：登录 / 注册。
  - 登录：账号、密码、保持登录 30 天、登录按钮。
  - 注册：昵称、确认密码、创建账号并开始引导。
  - “先看首次使用引导”入口（原型）。
  - 法律说明：服务条款、隐私政策、AI 解析单独授权。

### 1.3 状态

- 默认：登录。
- 注册：切换到注册，显示昵称/确认密码。
- 加载：按钮 loading，禁用重复提交。
- 错误：账号或密码错误、网络错误、CSRF/CORS 错误；错误信息在表单上方，保留输入。
- 锁定：登录限流 5 次/分钟/IP，展示“稍后再试”。

### 1.4 API

| 动作 | 接口 |
| --- | --- |
| 登录 | `POST /api/v1/auth/login` |
| 注册 | `POST /api/v1/auth/register` |
| 当前用户 | `GET /api/v1/auth/me` |
| 刷新 | `POST /api/v1/auth/refresh`（HttpOnly Cookie） |
| 登出 | `POST /api/v1/auth/logout` |

### 1.5 验收

- 登录成功进入 `/today`；注册成功进入 `/onboarding`。
- 不把 refresh token 写入 localStorage。
- 错误可读，按钮可键盘操作。

## 2. 首次引导 `/onboarding`

### 2.1 目标

2 分钟内完成档案、目标、导入和通知的最小配置。

### 2.2 步骤

| 步骤 | 内容 | 必填 | 可跳过 |
| --- | --- | --- | --- |
| 1 档案 | 时区、日界线、每日可用分钟、容量系数 | 是 | 否（有默认值） |
| 2 目标 | 岗位、城市、行业、公司类型、目标日期、优先级 | 岗位、日期 | 是 |
| 3 导入 | AI 授权、Markdown 上传/示例 | 授权（上传时） | 是 |
| 4 通知 | 企微 Webhook、早报/晚报/逾期/顺延开关 | 否 | 是 |

### 2.3 交互

- 顶部 4 步进度；已完成步骤显示勾选。
- 底部“上一步 / 跳过 / 下一步”；最后一步“进入工作台”。
- 步骤 1 实时计算有效容量：`floor(每日可用 × 系数)`，最低 30 分钟。
- 步骤 3 勾选 `ai_import` v1；不勾选不能上传。
- 步骤 4 Webhook 只接受 HTTPS 和企业微信固定域名；保存后只显示掩码。
- 关闭页面/刷新后保留已填写内容（正式版用草稿存储）。

### 2.4 API

| 动作 | 接口 |
| --- | --- |
| 保存档案 | `PATCH /api/v1/profile` |
| 保存设置 | `PATCH /api/v1/settings` |
| 创建目标 | `POST /api/v1/job-targets` |
| 授权 | `POST /api/v1/consents` |
| 上传计划 | `POST /api/v1/imports` |
| 通知渠道 | `POST /api/v1/notification-channels` |
| 通知偏好 | `PATCH /api/v1/notification-preferences` |

### 2.5 验收

- 4 步可前进/后退/跳过；数据不丢失。
- 容量公式实时更新，且与今日页有效容量一致。
- 未授权时不能触发 AI 解析。

## 3. 今日 `/today`

### 3.1 目标

回答“今天做什么、做了多少、接下来会怎样”，不要求用户整理待办。

### 3.2 布局

1. 页面头：日期、问候、目标提示（距目标天数）。
2. Hero：进度环、今日重点、容量、完成/顺延/累计活跃。
3. 容量条：已完成 / 待完成 / 缓冲。
4. 主网格：
   - 左：顺延区、今日任务、接下来。
   - 右：企微状态、执行摘要、规则提示。
5. 底部：路线预测 + 阶段时间线 + 风险。

### 3.3 任务卡

字段：类型、阶段/周、来源、预计时长、实际时长（完成后）、状态、“为什么今天做？”。

操作（详情抽屉）：

| 状态 | 可用操作 |
| --- | --- |
| pending | 开始、完成、延期、跳过、阻塞、拆分、放弃 |
| in_progress | 完成、延期、跳过、阻塞、拆分、放弃 |
| blocked | 解除阻塞、放弃 |
| postponed / skipped | 恢复到今日、放弃 |
| completed | 修改实际分钟、查看路线 |
| abandoned | 只读 |

### 3.4 完成弹窗

- 实际用时（默认计划分钟）、备注。
- 影响预览：路线进度 `62% → 64%`、预计完成日期。
- 确认后立即更新：进度环、完成数、容量条、路线进度、侧边栏路线进度、Toast。
- 已完成后再次打开可修改实际分钟，不重复增加完成数。

### 3.5 延期 / 跳过 / 阻塞 / 放弃 / 拆分

- **延期**：原因（可选）；旧实例 postponed，新实例明天，顺延次数 +1；提示预测日期变化。
- **跳过**：原因必填；计划日期清空；计入分母但不计完成。
- **阻塞**：原因必填；保持阻塞进入明天；解除后恢复 pending。
- **放弃**：二次确认；任务归档，不计入完成率分母。
- **拆分**：两个子任务标题/分钟；原任务归档，子任务进入今日。

### 3.6 空 / 完成态

- 无任务：容量 0/240，Hero 显示“今天没有安排任务”，任务区空态，提供“导入计划/从路线添加”。
- 全部完成：100%，Hero 显示“今天的计划已经完成”，不出现新的压力文案；保留“查看明天/提前做一项”。

### 3.7 API

| 动作 | 接口 |
| --- | --- |
| 今日视图 | `GET /api/v1/today` |
| 补生成 | `POST /api/v1/today/generate` |
| 开始 | `POST /api/v1/task-occurrences/{id}/start` |
| 完成 | `POST /api/v1/task-occurrences/{id}/complete` |
| 延期 | `POST /api/v1/task-occurrences/{id}/postpone` |
| 跳过 | `POST /api/v1/task-occurrences/{id}/skip` |
| 阻塞 | `POST /api/v1/task-occurrences/{id}/block` |
| 解除 | `POST /api/v1/task-occurrences/{id}/unblock` |
| 放弃 | `POST /api/v1/task-occurrences/{id}/abandon` |
| 拆分 | `POST /api/v1/task-occurrences/{id}/split` |

### 3.8 验收

- 完成/延期/跳过/阻塞/解除/放弃/拆分都有明确状态与反馈。
- 完成率按 occurrence 口径；abandoned 不进分母；skipped 进分母。
- 今日容量 ≤ 有效容量；超出显示 over_capacity，不静默丢弃。
- 所有数字与看板、路线详情一致。

## 4. 导入计划 `/import`

### 4.1 目标

把已有 Markdown 计划变成可执行路线，确认前可预览、编辑、取消。

### 4.2 状态机

```text
empty → processing → preview → done
                  ↘ error
preview → empty（取消/回滚）
processing → empty（取消）
```

### 4.3 上传卡

- 拖拽/选择 `.md`/`.markdown`，≤5MB，UTF-8。
- 首次导入授权：`ai_import` v1；未勾选时确认禁用。
- 下载 Markdown 模板；载入示例。
- 说明：导入失败不影响已有路线；产生执行记录前可回滚。

### 4.4 解析中

- 步骤：上传 → 规则抽取 → AI 标准化 → 校验与容量。
- Job ID、可离开页面、进度百分比、取消。
- 真实实现用 `POST /imports` + `GET /jobs/{id}` 轮询；Broker 不可用时请求内降级。

### 4.5 预览

- 文件信息；统计：阶段/周/任务/总分钟。
- 问题清单：错误/警告/提示；错误阻止确认。
- 任务树：阶段 → 周 → 任务；每条任务显示时长和 warning 图标。
- 内联编辑：标题、类型、分钟、产出、验收标准；保存后更新问题图标。
- 底部：取消、重新解析、确认并创建路线（授权后启用）。
- 重复任务：合并/保留/跳过；日期早于今天：整体平移/归档。

### 4.6 成功 / 失败

- 成功：42 任务、3 阶段、6 周、v1；查看路线、回滚、再导入。
- 失败：错误码 `IMPORT_PARSE_FAILED`、request_id、重新上传、下载模板。
- 回滚：二次确认；已产生执行记录时正式版阻止。

### 4.7 API

| 动作 | 接口 |
| --- | --- |
| 上传 | `POST /api/v1/imports` |
| 详情 | `GET /api/v1/imports/{id}` |
| 预览 | `GET /api/v1/imports/{id}/preview` |
| 确认 | `POST /api/v1/imports/{id}/confirm` |
| 取消 | `POST /api/v1/imports/{id}/cancel` |
| 回滚 | `POST /api/v1/imports/{id}/rollback` |
| Job | `GET /api/v1/jobs/{id}` |

### 4.8 验收

- 60 秒内完成结构化样本解析。
- 预览可编辑并重新校验；错误不能确认。
- 失败不影响已有路线；确认幂等；回滚可用。

## 5. 学习路线 `/routes`

### 5.1 目标

管理路线、阶段、周和任务的层级结构，明确当前执行/草稿/暂停状态。

### 5.2 列表

- 3 个摘要卡：当前执行路线、路线任务、预计完成。
- 路线行：名称、目标、状态、任务数、已完成、计划分钟、进度、预测风险。
- 操作：查看详情、暂停/恢复、更多（调整/版本/归档）。
- 新建空路线：名称、目标、开始日期、每日分钟；创建为草稿。
- 空状态：导入 Markdown / 新建空路线；隐藏摘要卡。

### 5.3 详情

- 返回链接、路线 Hero（名称、目标、周期、状态、版本）、主要操作。
- 4 个摘要：周期、任务/完成、进度、预计完成。
- Tabs：阶段与任务 / 版本记录 / 路线设置。
- 阶段折叠 → 周折叠 → 任务表格（任务、类型、时长、计划日、操作）。
- 版本：v3/v2/v1，时间、说明、查看快照。
- 设置：开始日期、每日分钟、系数、影响预览、保存并重排、归档。

### 5.4 规则

- 同一目标下只保留一条执行中路线。
- 删除是归档，不物理删除；历史 occurrence 保留。
- 有任务的阶段/周删除返回 409。
- 调整日期/容量会平移未完成阶段和任务，并生成新版本。
- 升级/回滚不改写已产生的执行记录。

### 5.5 API

| 动作 | 接口 |
| --- | --- |
| 列表/创建 | `GET/POST /api/v1/routes` |
| 详情/更新 | `GET/PATCH /api/v1/routes/{id}` |
| 激活/暂停/恢复/归档 | `POST /api/v1/routes/{id}/(activate|pause|resume|archive)` |
| 调整 | `POST /api/v1/routes/{id}/adjust` |
| 预测 | `GET /api/v1/routes/{id}/forecast` |
| 阶段 | `POST /api/v1/routes/{id}/stages` |
| 周 | `POST /api/v1/stages/{id}/weeks` |
| 任务 | `POST /api/v1/tasks` |
| 版本 | `GET /api/v1/routes/{id}/versions` |

### 5.6 验收

- 路线/阶段/周/任务 CRUD 与状态流转符合文档 §3.4。
- 调整有影响预览；删除有 409 提示；归档保留历史。
- 移动端表格可读，隐藏计划日列。

## 6. 执行看板 `/dashboard`

### 6.1 目标

只看执行：完成率、时间、顺延、活跃、预测；不显示能力分。

### 6.2 指标

| 指标 | 口径 |
| --- | --- |
| 计划完成率 | 完成 occurrence / 计划 occurrence |
| 计划 / 实际分钟 | Σ planned / Σ actual |
| 顺延率 | carry_over_from_id 非空 / 计划 occurrence |
| 累计活跃天数 | 历史有完成记录的天数，不清零 |
| 路线进度 | 完成任务数 / 总任务数（按 task 去重） |
| 预测完成日期 | 剩余分钟 / 近 14 天吞吐 |
| 风险 | 预测日期 > 目标日期 |

### 6.3 结构

- 4 个 KPI。
- 7/30 天切换；30 天包含未开始计划的空白天。
- 趋势柱状图：计划/完成/顺延；图例 + 总计 + 口径说明。
- 任务分布：类型条；状态环（完成/顺延/跳过/阻塞）。
- 路线进度：3 条路线。
- 预测与风险：日期、目标、剩余任务/分钟、吞吐、建议。
- 后续能力：Phase 2 代码评分、Phase 3 完整能力锁定说明。
- 指标口径折叠。

### 6.4 空状态

- 无执行记录：隐藏全部图表，显示“还没有可统计的执行记录”，提供导入/今日入口。

### 6.5 API

| 动作 | 接口 |
| --- | --- |
| 总览 | `GET /api/v1/dashboard/overview` |
| 趋势 | `GET /api/v1/dashboard/trends` |
| 分布 | `GET /api/v1/dashboard/distribution` |
| 预测 | `GET /api/v1/dashboard/forecast` |

### 6.6 验收

- 数字能与今日页、路线详情、数据库对账。
- 没有假能力分；Phase 2/3 明确锁定。
- 7/30 天切换不出现空白天错位。

## 7. 设置

### 7.1 档案与容量 `/settings/profile`

- 时区、日界线、每日可用分钟、容量系数、有效容量。
- 求职目标：岗位、城市、目标日期、行业、优先级；主目标状态。
- 计划偏好：自动顺延、空计划、询问实际分钟。
- 保存只影响未来计划，不改写历史。
- API：`GET/PATCH /api/v1/profile`、`GET/PATCH /api/v1/settings`、`GET/PATCH /api/v1/job-targets`。

### 7.2 企业微信推送 `/settings/notifications`

- 渠道卡：已连接、Webhook 掩码、最近测试、测试发送、更换、断开。
- 事件表：早报 07:30、晚报 20:30、逾期 20:00、顺延 04:10、周总结周日 20:00；时间可改、可开关。
- 免打扰：开始/结束、延迟/丢弃策略。
- 最近发送：sent/retry/dead、手动重发/重新入队。
- API：`GET/POST /api/v1/notification-channels`、`POST /{id}/test`、`GET/PATCH /api/v1/notification-preferences`、`GET /api/v1/notification-outbox`、`POST /{id}/resend`。

### 7.3 AI 授权 `/settings/ai`

- 状态：已授权/未授权；scope `ai_import`、version v1、授权时间、最近使用。
- 撤销/重新授权；撤销后不能导入，但已有路线可用。
- Provider：Stub / 未配置真实模型；不静默降级。
- 数据边界：只发计划文本；AI 输出需校验和确认；不执行代码/不评分。
- API：`GET/POST /api/v1/consents`。

### 7.4 数据与账号 `/settings/data`

- 账号信息、退出登录、刷新会话。
- 导出全部数据（后续）、删除账号（后续，二次确认 + 邮件）。

## 9. 文案规则

- 标题用“做什么”，不用“欢迎来到……”。
- 主按钮动词明确：`开始下一项`、`完成并记录`、`确认并创建路线`。
- 不使用“加油”“坚持”“打卡失败”等制造压力的词。
- 说明数字口径时用短句，不写长篇解释。
- 空状态提供下一步动作，不只说“暂无数据”。
- 风险文案给替代方案，不只报错。

## 10. 响应式与可访问性

- 断点：1200 / 1024 / 860 / 640 / 420。
- 860 以下：侧边栏 → 底部导航；卡片单列；顶栏简化。
- 640 以下：任务行两列；表单单列；设置导航 2×2；弹窗底部抽屉；表格隐藏计划日列。
- 触控目标 ≥ 44px；状态不只靠颜色；所有图标按钮有 aria-label。
- 抽屉/弹窗 Esc 关闭，打开时焦点进入，关闭后回到触发元素。
- 图表有 aria-label；进度环有文本百分比。
- `prefers-reduced-motion` 关闭过渡。
