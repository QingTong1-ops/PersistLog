## 0. 这一版调整了什么

v1 原型已经确定了“静谧推进”的视觉方向和今日页的基础结构，但部分内容仍混入了 Phase 2/3 的设想。本版根据当前产品文档收敛为 **Phase 1 可交付初稿**：

1. **补齐 Phase 1 页面**：登录/注册、4 步首次引导、导入预览、路线详情/版本、设置（档案、企微、AI 授权、数据）、空/错/完成状态。
2. **移除 Phase 1 不存在的 AI 教练、能力差距和已具备能力**：Phase 1 的 AI 只做计划结构化；看板只做执行进度，不显示没有证据的能力分。
3. **统一信息架构**：`/today`、`/import`、`/routes`、`/routes/{id}`、`/dashboard`、`/settings/*` 与产品文档 §4.1 对齐。
4. **统一数据口径**：容量、任务数、路线进度、预测日期、目标日期在同一份演示数据上对账，避免“今日 2/5、看板 5 天、路线 26/42”互相矛盾。
5. **补齐关键交互状态**：完成、延期、跳过、阻塞、解除、放弃、拆分；导入中、导入失败、导入成功；路线暂停/恢复/归档；AI 授权撤销。
6. **移动端改为底部导航**：今日 / 看板 / 路线 / 我的，不再把“复习”放进 Phase 1；导入从今日/路线入口进入。
7. **修正原型的可访问性与细节**：焦点环、键盘可操作、状态不只用颜色、进度环有文本百分比、窄屏单列。

## 1. 设计方向：静谧推进 Quiet Momentum

恒序不是制造压力的打卡工具，而是帮助用户持续向目标岗位靠近的个人执行系统。

视觉需要同时传达：

- **秩序感**：路线 → 阶段 → 周 → 今日任务的关系清楚。
- **技术感**：适合计算机专业求职场景，但不做成代码编辑器。
- **成长感**：强调“今天比昨天更接近目标”，不强调连续打卡。
- **陪伴感**：系统是教练和记录者，不是批评者。

关键词：`克制`、`清晰`、`坚定`、`有证据的成长`。

### 1.1 设计原则

1. **今天优先于全部**：打开产品先看到今天能做什么，而不是历史报表。
2. **容量优先于愿望**：每日计划必须有上限，宁可少而完成。
3. **行动优先于评分**：没有证据的能力显示“未评估”，不编造分数。
4. **确认优先于自动**：AI 可以解析，但路线和计划的大改必须由用户确认。
5. **零整理**：用户每天只确认、完成、跳过，不要求重新维护待办。
6. **可恢复**：延期、跳过、归档都保留来源；高风险操作可撤销。

## 2. 品牌视觉语言

### 2.1 品牌图形

由两条递进曲线和一个定位点组成：

- 两条曲线代表计划与执行。
- 定位点代表当前能力位置。
- 向右上方的走势代表持续进步。

不使用火焰、奖杯、连续打卡等强游戏化元素。品牌标记为紫色渐变圆角方块，用于侧边栏、登录页和空状态。

### 2.2 视觉层级

1. 今日最重要的行动（Hero + 今日任务）。
2. 目标岗位差距和当前进展（路线预测、风险）。
3. 执行证据与提示（容量、顺延、提示卡）。
4. 详细记录和配置（路线详情、设置）。

- 红色只用于阻塞和真正影响计划的风险。
- 状态标签同时包含文字和颜色，不依赖色点单独传达状态。

## 4. 字体与排版

```css
font-family: Inter, "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
```

- 页面标题：28–32px，字重 700–780，`letter-spacing: -0.04em`。
- 卡片标题：15–18px，字重 650–720。
- 正文：13–14px，行高 1.65。
- 辅助信息：10–12px，颜色 `--ink-600`。
- 数字指标：24–36px，`font-variant-numeric: tabular-nums`。
- 中文标题避免孤字成行；登录页主标题用主动换行。

## 5. 组件规范

### 5.1 卡片

- 背景白色，圆角 20px，边框 `1px solid var(--line)`。
- 阴影只在悬停或重点卡片使用；默认阴影极轻。
- 内边距 18–24px；卡片头、正文、底部分区。

### 5.2 按钮

- 主按钮：品牌紫，白字，圆角 10px，高度 38px。
- 次按钮：白底、边框、深色文字。
- 文字按钮：无背景，品牌色。
- 破坏性操作：珊瑚色，并明确操作对象。
- 深色 Hero 上使用白色按钮或半透明描边按钮。
- 所有按钮支持 `:focus-visible` 焦点环。

### 5.3 状态标签

- `已完成` / `进行中` / `待开始` / `已移明天` / `已跳过` / `已阻塞` / `已放弃`。
- 标签同时包含文字和色块；阻塞与风险使用珊瑚色。
- 顺延标签显示次数，例如“顺延 1 次”。

### 5.4 进度表达

- **进度环**：今日完成度，中心必须有百分比文本。
- **横向进度条**：路线进度、容量使用。
- **分段容量条**：已完成 / 待完成 / 缓冲。
- **趋势柱状图**：7 天或 30 天，计划 / 完成 / 顺延三组。
- **时间线**：路线阶段和预测。
- **证据列表**：Phase 3 能力区使用，Phase 1 只显示锁定说明。
- 避免“只有一个大数字、没有口径”的评分。

### 5.5 任务卡

每条任务包含：

- 类型（算法/八股/工程/项目/简历/面试/复盘）。
- 阶段/周，来源（路线/顺延/手动/系统）。
- 预计时长，完成后显示实际时长。
- “为什么今天做？”入口。
- 状态操作：开始、完成、延期、跳过、阻塞、解除、放弃、拆分。

桌面端为一行式，移动端把时长和状态移到第二行。

### 5.6 空 / 加载 / 错误 / 完成态

- **空**：无路线、无任务、无执行记录、无通知。
- **加载**：导入解析 Job、AI 标准化、今日计划生成。
- **错误**：`IMPORT_PARSE_FAILED`、Webhook 失败、AI 未配置。
- **部分完成**：实际分钟未填、导入 warning、任务阻塞。
- **完成**：今日全部完成，不追加“继续加油”式压力文案。

## 7. 首页（今日）内容

首页第一屏展示：

1. 当前日期、问候语、距目标天数。
2. 今日完成度进度环。
3. 有效容量、已排入分钟、剩余缓冲。
4. 今日最重要的 3–6 项任务。
5. 顺延任务区（数量、连续顺延次数、优先开始）。
6. 企微早报/晚报状态。
7. 近 7 天执行摘要。
8. 规则型执行提示（不是 AI 评分）。
9. 路线预测、目标日期和风险。

**不展示**：AI 教练建议、能力差距、已具备能力、准备度分数。这些属于 Phase 3；Phase 1 没有证据就不显示。

### 7.1 演示数据口径

为保证页面之间可对账，本版统一使用：

- 今天：2026-10-19 周一，目标 2026-11-10。
- 每日可用 300 分钟 × 80% = **240 分钟有效容量**。
- 今日 5 项、计划 220 分钟、缓冲 20 分钟；初始完成 2 项，实际 85 分钟。
- 路线：36 天，42 个任务，已完成 26 项，进度 **62%**。
- 预测完成 2026-11-12，晚于目标 2 天。
- 近 7 天：计划 38、完成 28（74%）、顺延 5（13%）、计划/实际 620/578。
- 累计活跃 12 天（不是连续打卡）。

## 8. 关键页面设计

### 8.1 登录 / 注册

- 左侧深墨蓝品牌叙事，右侧白色表单卡。
- 登录：邮箱/手机号、密码、保持登录 30 天。
- 注册：昵称、确认密码。
- 说明 Access Token 在内存、Refresh Token 在 HttpOnly Cookie。
- 原型提示和“先看首次使用引导”入口，方便评审。

### 8.2 首次引导

- 4 步：档案与容量 → 求职目标 → 导入计划 → 企业微信。
- 每一步都有“为什么”说明，不堆字段。
- 支持跳过；导入授权可单独勾选。
- 右侧说明卡解释容量公式和完成后得到什么。

### 8.3 导入计划

- 上传卡片常驻，右侧状态卡在空 / 解析中 / 失败 / 预览 / 成功之间切换。
- 首次导入必须勾选 `ai_import` 授权，未勾选时确认按钮禁用。
- 解析中展示 Job ID、步骤和进度；可取消。
- 预览：3 阶段 / 6 周 / 42 任务 / 1,260 分钟；问题清单（错误/警告/提示）；阶段-周-任务树；内联编辑。
- 确认后显示成功态：查看路线、回滚、再导入。
- 失败态展示错误码和 request_id；可重新上传或下载模板。

### 8.4 学习路线

- 列表：执行中 / 待确认 / 已暂停，显示任务数、已完成、计划分钟、预测风险。
- 详情：路线 Hero、4 个摘要指标、阶段与任务、版本记录、路线设置。
- 阶段用折叠面板，周用二级折叠；任务表格在移动端隐藏计划日列。
- 调整开始日期/容量时显示“阶段后移 N 天、预测日期变化”的影响预览。
- 删除语义为归档；有任务的阶段/周删除返回 409（正式版提示）。

### 8.5 执行看板

- 4 个 KPI：完成率、计划/实际分钟、顺延率、累计活跃天数。
- 7/30 天切换；30 天视图前面保留未开始计划的空白天。
- 趋势柱状图：计划 / 完成 / 顺延。
- 任务分布：按类型；状态环：完成/顺延/跳过/阻塞。
- 路线进度、预测与风险。
- Phase 2/3 能力区锁定说明：代码评分趋势、完整能力与准备度。
- “指标口径”折叠说明，明确完成率、顺延率、路线进度、活跃天数、预测的定义。

### 8.6 设置

- 档案与容量：时区、日界线、每日分钟、容量系数、有效容量、目标。
- 企业微信：渠道、测试发送、5 类事件、免打扰、最近发送（Outbox 重试/dead）。
- AI 授权：scope/version/时间、撤销/恢复、Provider 状态（Stub）、数据边界。
- 数据与账号：导出/删除（后续）、审计、登录设备、退出。

## 9. 交互原则

- 首页默认展示“今天可以做什么”，不展示全部历史。
- 每个任务都有明确动作和产出；点击任务打开详情抽屉。
- 完成任务立即更新今日完成度、容量、路线进度和预测；用 Toast 说明影响。
- AI 建议必须提供“为什么这样建议”的证据入口；Phase 1 的提示是规则型，不伪装 AI。
- 顺延时显示影响范围和新预测日期；连续 3 次提示拆分/降级/放弃。
- 高风险操作可撤销或恢复；放弃任务不计入完成率分母。
- 空计划也保留记录，避免推送/看板断裂。

### 9.1 状态流转

```text
pending → in_progress → completed
pending / in_progress → postponed / skipped / blocked / abandoned
blocked → pending
```

- `postponed`：旧实例终态，新实例进入下一天，顺延次数 +1。
- `skipped`：写原因，计划日期清空，不再自动进入今日。
- `blocked`：写原因，不自动变 pending；解除后恢复。
- `abandoned`：终态，任务归档，不计完成率分母。

## 10. 可访问性与响应式

- 正文与背景对比度至少 WCAG AA；状态不只靠颜色。
- 所有按钮可键盘操作；抽屉/弹窗有焦点管理，Esc 关闭。
- 进度环提供文本百分比；图表提供 `aria-label` 和文字总计。
- 移动端底部导航、44px 触控目标、单列卡片。
- `prefers-reduced-motion` 下关闭过渡。
- 低宽度下表格隐藏次要列，详情抽屉全宽。
